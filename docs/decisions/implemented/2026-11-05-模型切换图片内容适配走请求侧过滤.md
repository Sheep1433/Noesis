# 决策：模型切换的图片内容适配走请求侧过滤（UnsupportedContentMiddleware）

状态：implemented
日期：2026-11-05

## 问题

会话中途切换模型（VL ↔ 非 VL）时，VL 轮注入的图片内容块
（`image_url` / read_file 二进制 `image`）留在消息状态里，随每次模型请求
原样发给当前模型：严格的 OpenAI 兼容端点直接 400 整轮失败；宽容网关静默
丢弃或白白传输 base64。全仓此前没有任何图片内容剥离点。

## 决策

模型调用边界请求侧过滤：`UnsupportedContentMiddleware` 挂中间件栈
HITL 之前（HITL 最内层契约不变），对**每次请求**的全部 HumanMessage /
ToolMessage 把当前模型不支持的图片块替换为文本占位符（携带
read_file_path / mime，模型知道自己错过了什么）。**消息状态不动**——
切回 VL 模型时图片自动恢复生效，双向切换安全。

能力判定：请求时从 `request.model` 取 `model_name`（覆盖
`.model_name`/`.model` 两类 wrapper），按 `model_name_supports_vision`
名字 hints 判定；取不到模型名时放行（fail-open，与 deepagents
「profile 缺失按支持处理」语义一致）。

## 备选方案

- **升级 deepagents ≥0.7.3x 直接用上游 `UnsupportedContentMiddleware`**：
  被否——上游按 `model.profile`（ModelProfile）判定，Noesis 的模型对象
  未填 profile，fail-open 语义下等于不过滤；补 profile 元数据 + 大版本
  升级（0.6.12 → 0.7.32，filesystem 深耦合适配）成本远高于 ~90 行同构
  实现。设计照抄（请求侧过滤 + 状态保留 + 占位符告知），判定机制本地化。
- **input_resolver 每轮重写历史消息（状态侧剥离）**：被否——状态被改写
  后切回 VL 模型图片无法恢复，单向有损；且需回改已 checkpoint 的历史。
- **发送前丢弃图片块不告知**：被否——模型不知道存在被省略的内容，
  回答会出现"看不见但不知道自己看不见"的静默盲区。

## 代价

- 每次模型请求多一遍消息块扫描（非 VL 模型才发生实际改写），纯内存
  遍历，可忽略。
- 名字 hints 判定（`vl`/`vision`/`omni`/`gpt-4o`/`gemini`）依赖命名惯例：
  名字不带 hints 的 VL 模型会被误过滤、名字碰巧含 hints 的非 VL 模型
  不被过滤——与既有 `is_vision_available` 同源风险，catalog 显式标注
  能力是长期解（对齐上游 ModelProfile 方向），进 backlog。
- AIMessage 内容不参与过滤（图片块只出现在 human 输入与工具结果）；
  音频/视频/文件块暂不在过滤面（Noesis 附件面只产图片与文档）。
