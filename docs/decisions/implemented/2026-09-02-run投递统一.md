# 决策：主/子 Agent run 事件投递与前端流消费的统一方式（unify-run-delivery）

状态：implemented
日期：2026-09-02

## 问题

主会话与子 Agent run 存在两套平行实现：同一订阅端点 `/runs/{run_id}/stream` 按 origin 分叉成两套事件方言与两份投递总线（RunManager sequence buffer vs executor 内存 history deque），前端相应两套 SSE 消费（`useSSEStream` vs 子会话内联解析）与两套领域状态。上一轮统一只收了执行内核，此后每个新能力（实时统计、流式 delta、断流自愈）都落在边界两侧各写一次——债随迭代再生产。审计另坐实：子 Agent stop 响应 `to_dict()` 500、`citationIndex` prop 被共享渲染器静默丢弃、`check_task` pending 提示不可达。

## 决策

五层统一（openspec 变更 `unify-run-delivery`，阶段 0-3b 已实施，阶段 4 宿主壳部分完成）：

1. **投递内核单点**：`chat/runs/delivery_bus.py` 的 `DeliveryCore`——被动数据结构（无自有锁，持有方锁内调用，保住「sequence 与 projection 原子一致」），提供 sequence 分配、有界缓存、连续性重放、transient 旁路。RunManager 组合它（`RunHandle.delivery`）；executor 以 `_RUN_DELIVERY` 注册表按 run 持有实例，序号与 DB 检查点 guard 同号（一个数空间，检查点序号=最后一帧序号——避免缓存断档）。
2. **wire 词汇一套**：终态 typed 事件统一编码 `run.finished`（`finish`/`abort`/`error` 编码名退役，编码与解码同改维持 TEST_CASE 往返环）；`RunPaused(hitl_pending)` 走 `run-status` 非终态；子 Agent 全帧转发（`message.updated` 全量投影退役），子会话内容投影由前端 `messageParts` appenders 组装（与主聊天同一实现，经共享 `createFrameHandlerTable` 分派表）。
3. **检查点事务单点**：`persist_projection` 裸 SQL 退役，改经 `AgentRunRepository.save_checkpoint`（主/子同一事务实现），DB 抖动按主链路同款有界重试。
4. **前端传输内核**：`useRunStreamClient.ts`（SSE 解析含 `[DONE]`/CRLF、45s 读超时、退避重连可被 abort 打断、断流权威快照收口钩子、重试耗尽回调）。主 run 流、会话信令流、子会话流三处换用；子会话补齐读超时与重试耗尽可见失败（此前静默卡「生成中」）。
5. **样板收敛**：骨架行构造（`chat/runs/skeleton.py`）、usage 合并（`merge_usage`/`merge_model_calls`，step 全局重编）、终态映射（`ASSISTANT_TERMINAL_STATUS`）、child 目录摘要（端口模块纯函数）、重启对账 scope 互斥（通用 recovery 显式排除 subagent）、写操作族 CSRF、类型化异常 409/404。宿主壳共享组件：`AssistantToolFailureBlocker`、`SessionStatsLine`、`StopSendButton`、`useTicker`。

## 备选方案

- **子 Agent run 并入 RunManager 注册表**：否决。producer 生命周期模型不同（RunManager 管 producer/resume vs executor 管 turn 循环）、隔离 loop 与主 loop 桥接复杂度不对等；并入等于把两套复杂性焊成更大的单体。
- **保留双方言、只统一传输契约**：否决。词汇分叉是「每个新能力写两次」的再生产根源，不除根。
- **主聊天迁 run 级投影词汇**（向 `message.updated` 收敛）：否决。投影词汇表达不了 redacted-thinking 缓冲、`parent_task_call_id` 嵌套、压缩边界；894 行 useSSEStream 与 chat.vue 的咬合面重写风险倒挂。
- **executor 挂 RunProjection（双 builder 镜像）**：实施期否决。与 3b 前端组装架构冗余且引入与主链路相同的双装配（每 token 两份内存写）；实质统一件是检查点事务单点，已落地。主链路自身的 service builder 双装配经审计确认（happy path 仅错误兜底消费），修复列为后续小改。
- **投递内核做成自锁组件**：否决。RunManager 在 RunHandle lock 内完成 sequence+checkpoint+buffer，自带锁即破坏原子不变量——内核必须是被动数据结构。
