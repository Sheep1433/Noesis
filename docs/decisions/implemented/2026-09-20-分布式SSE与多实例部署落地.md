# 决策：分布式 SSE 与多实例部署（enable-distributed-sse-pubsub 落地）

状态：implemented
日期：2026-09-20

## 问题

单实例架构不可横向扩展：Web/SSE worker 无法增加，非 Run owner 进程不能实时订阅、停止或恢复 HITL。解决路径是单 execution leader + 多 Web worker（Redis Pub/Sub 广播 + PostgreSQL 权威），openspec `enable-distributed-sse-pubsub` 变更承载。本记录沉淀落地阶段的四个关键实现决策与被否方案。

## 决策

### 1. 选双模式共享一套状态机，发布挂点选 `_fanout`

`NOESIS_RUN_BUS_BACKEND=memory|redis` 只换 transport，不分支业务（queued dispatch / durable command / checkpoint / 订阅状态机共用）。Run 事件的发布挂点选 `RunManager._fanout`：终态事件天然在 PostgreSQL 终态事务提交后才走到该点、CAS 输家发布的是权威 snapshot replacement——spec 的「terminal 先落库再 publish / CAS loser 不发候选终态」两条约束零额外代码成立。wire 载荷与 SSE 编码同源（`sequenced_event_payloads`），远端 worker 产出与直连 leader 逐字节一致的帧。

### 2. follower 候选挂 elector 晋升回调，recovery 随晋升而非仅启动

`LeaderElector.run_as_worker`（redis 模式）：拿不到锁即 follower 待命 + 5s 重竞选；晋升（含进程启动首例）回调 `_on_promotion` 承载 leader 面装配与**四段 recovery**（主 Run / 子代理 Run / 定时任务记录 / 通知装载），全部完成后才 dispatch。修正了原 design「recovery 只在 lifespan 跑一次」与运行中切主矛盾的过时假设。同进程模拟暴露 `try_advisory_lock` 的双重持有缺陷（conn 缓存使同 manager 二次 try 返回 True），修正为「已持锁返回 False」。

### 3. 信令与子会话事件走「桥 + 复用」而非新总线

三类信令（user/session/bg-tasks）与子会话 RunEvent 不建新基础设施：`SignalBridge` 桥接三个既有本地总线（本地 fan-out 不变 + 发布上 bus + 每 (scope,key) 一份远端泵投回 + origin 回声抑制），端点代码零改动；子会话事件复用 Run bus 的 Run channel（envelope 天然同构），follower 用 4.3 的 RunHub 恢复。被否：子会话端点 leader-only + 网关亲和（leader 故障期页面不可用，削弱多实例收益）。

### 4. stop/HITL/后台任务停止统一 durable command

`t_agent_run_command`（`(user_id, dedupe_key)` 唯一幂等；HITL 附 decision digest，异决策 409）+ leader consumer（wake-up + 补扫 + 失锁门控）。API 响应**增量兼容**：`{**snapshot, command_id, command_status}`——老消费者零破坏；`submit_and_wait` 5s 有界等待，accepted 不伪装完成，前端任务取消按状态分流提示。

## 备选方案

- **Redis Streams 替代 Pub/Sub**：被否。PostgreSQL 已是恢复与终态权威，需要的是在线广播不是第二套 durable log。
- **按 Run lease / 多 execution leader**：被否（Non-Goal）。当前单 leader 容量未成瓶颈，先观测再设计分片。
- **子会话投递内核（DeliveryCore）并入 RunManager**：暂缓。两执行面的类型化事件/wire dict 形状差异使合并属行为邻近重构，本轮以「端点层统一 wire 消费循环（`_wire_sse_stream`）」收敛三份重复循环；合并记为独立后续项。
- **调度器 tick 串行保留**：被否。redis 模式下与 dispatcher/SSE 共享 leader loop，慢定时任务会拖垮 Web 实时面——迁移计划第 0 步先行异步化（tick 只领任务、执行甩出、成功判定挂交付链收口）。

## 代价

- Redis 成为 redis 模式的运行依赖：降级策略为「Web 可路由、新 Run 503、已有 Run 查询/stop/HITL 可用」；Pub/Sub at-most-once 的丢失窗口由握手/对账机制兜底。
- 每事件一次跨 loop 发布（fire-and-forget）+ 信令三通道广播；同 worker 多 Tab 经 hub 复用一份订阅，放大成本受控。
- 迁移新增两表（`bg_task_notifications`、`t_agent_run_command`）；command 保留期 7 天既是清理窗口也是去重窗口。
- 双进程 E2E（跨 worker 多 Tab Playwright）、100 active Run 容量报告与 staging 故障演练（Redis 重启/滚动发布）不在本仓库 CI 内，归 staging runbook（tasks 8.2–8.4 标注）。
