# 决策：研究来源的采集、跨边界传递与展示分层（research-source-provenance）

状态：implemented
日期：2026-08-31

## 问题

深度研究会话的来源溯源存在结构断裂：主 run 桥接层把检索工具输出解析为结构化 retrieval parts，子 Agent 会话投影却只生成 text/tool parts（同一消息格式两个生产者，检索解析只接主轨，而子 Agent 承担深度研究绝大部分检索）；子 Agent 终态回传（通知注入、`check_task`）只回传小结文本，来源结构在边界处丢弃，主 Agent 来源面板在深度研究轮次常常为空。「来源 N」不分引用与检索（抓 8 条用 1 条也计 8 条）；异步续跑把一轮研究拆成多条消息（派发/进度/交付），按消息挂面板永远挂不对位置，会话级聚合又会把相邻多轮研究的来源混在一起。

## 决策

openspec 变更 `research-source-provenance`（18/18 已实施，归档 2026-09-03）：

1. **解析下沉单点**：`retrieval_payload → {query, results, truncated}` 与 retrieval part 构造抽为共享模块（`noesis/chat/event_mapping/retrieval.py`），主 run 桥接层与 executor 子会话投影同调；只下沉 part 构造这一层，桥接层其余职责不动。
2. **跨边界在收取点结构化落位**：子 Agent 终态从子会话 retrieval parts 提取去重来源清单（canonical URL 归一化、有界），经既有通知通道与 `check_task` 返回携带；主 run 桥接层登记为带 origin 标记（`{kind: subagent, label: 任务标题}`，缺省 main 向后兼容）的 retrieval parts，落在收取发生的那条消息上。数据落位与展示位置解耦。
3. **研究弧聚合**：弧 = 一条真实用户消息（`source_kind != bg_task_notice`）到下一条真实用户消息之间的全部 assistant 消息；过程消息不渲染面板，弧内最后一条消息渲染该弧全部落库 parts 的聚合面板。弧边界仅由消息历史决定。
4. **引用三层判定**：结构化引用标记 `[citation:标题](ref)`（与 CITATION_EXTENSION prompt 协议同语法）按 ref 精确命中 → 模型残缺标记按 host/标题宽容匹配 → 裸 URL canonical 兜底；归因文本 = 交付消息顶层正文 + 弧内 write_file/edit_file 写入正文（报告本体即交付物）。面板标题「引用 M · 共检索 N」。
5. **来源身份 canonical URL**：去 tracking 参数、统一协议与 host 大小写；前后端共享归一化规则；同 URL 多贡献者合并为单条目（origin 数据保留落库、不用于展示分组）；去重作用域为子会话内与研究弧内，跨弧不渗透。
6. **面板纯函数不变量**：retrieval parts 只追加不回写历史、弧边界确定性、面板 = 弧内落库 parts 合并去重的纯函数——刷新重算不变，多轮互不渗透。

## 备选方案

- **按贡献者（子 Agent 任务）分组展示**：2026-08-31 用户裁决否决——平铺展示，引用项在前、其余检索来源折叠其后；origin 归因仅落库供后续 harness 消费。
- **run 级 source id 映射（ChatGPT/Perplexity 式生成时打标 id）**：否决。子 Agent 跨边界时 run-local id 无法解析；citation 标记采用自包含引用（标题 + URL/kb ref 逐字复制自工具结果），子 Agent 来源经登记进主会话后标记 ref 天然命中，无需跨 Agent id 映射。
- **服务端算法归因（Gemini 式 claim-to-source binding）**：否决。平台 SHALL NOT 解析模型 Markdown 反推绑定；把判定留在「标记 + URL 匹配」的确定性层。
- **面板计数按单工具调用条数上限截断**：否决。「共检索 N」须反映真实检索量，截断会让计数失真；改为跨边界清单上限 200（MAX_CROSS_BOUNDARY_SOURCES）。

## 代价与遗留

- 引用判定存在召回缺口：模型转述事实不附 URL 也不输出标记时该来源不计入引用（引用数偏低）；残缺标记的 host/标题宽容匹配有小概率误命中，仅作线索层。
- 子会话落库体积增长（retrieval parts 入 assistant 消息），沿用 `tool_output_max_chars` 与结果条数上限约束。
- 进行中的弧随新消息推进，面板位置随之移动（交付前中间态），属预期行为。
- harness（research harness）落地时数据源将从「收取时登记清单」升级为证据升级链路、来源身份升级为 canonical URL + 正文 hash；本变更的数据字段（origin、sources 清单）已按 harness 可消费形态设计，展示模型与纯函数不变量不推翻。
