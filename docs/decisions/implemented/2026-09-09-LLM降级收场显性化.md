# 决策：LLM 降级收场显性化——事件流层补 error 终态

状态：implemented
日期：2026-09-09

## 问题

LLM 错误中间件重试耗尽/不可重试（网关欠费 402、首请求超时等）时返回带
`noesis_model_fallback` 标记的降级 AIMessage，并发 `noesis_model_fallback`
custom 事件。两条既有消费路径都正确处理：生产 SSE 桥接层把失败文案推入
消息体并标 error 终态；子 Agent executor 据标记把 run 改判非 completed。
但**直接消费 `SuperAgent.run_agent` 事件流的路径**（noesis CLI、离线评测）
两样都没接：降级消息不经 `on_chat_model_stream`（无真实流式输出）、
custom 事件无人消费，run 以 `finish_reason=stop` 正常收尾——基础设施
故障伪装成「正常空完成」。评测实测两次：402 批次 8 样本全部落盘为
completed=True + 空 final_text；网关首请求 APITimeoutError 同样空收场。

## 决策

在 `runtime/stream.py` 的 `stream_agent_events`（事件流唯一收口）跟踪降级
信号——`noesis_model_fallback` custom 事件（真实路径：模型调用在中间件层
被短路，没有 model_end 事件）或带标记的 `on_chat_model_end` 输出，成功的
模型输出到达则清除（跨轮恢复语义）。收尾时若降级仍在：发
`__tw_error__`（内容为中间件失败文案）+ `finish_reason=error`，不再发 stop。

SSE 桥接层 `__tw_error__` 处理器补幂等（`_finish_emitted` 时直接返回）：
生产路径 custom 事件已发过 error 终态，合成 error 不得双发。

同批修复评测侧三处缺口：记忆评测正例附加单回合约束后缀（对齐 deepresearch
线，堵住「委派后台子 Agent 后交过程叙述」的失败模式）；正例 raw 记录补落
`tool_outputs`（归因可观测性）；`cli_driver` 为 CLI 子进程注入
`REQUEST_TIMEOUT`/`STREAM_IDLE_TIMEOUT` 长超时（deepresearch 线同款值，
env 显式设置时不覆盖）。

## 备选方案

- **只在评测/CLI 收集器里识别降级**：否——洞在事件流收口，每个新消费方
  都要重新接一次；且 SuperAgent.run_agent 的任何未来调用方都会踩同一个坑。
- **让中间件在降级时抛异常而非返回降级消息**：否——生产 SSE 路径依赖
  降级消息把失败文案写进消息体（用户在消息里看到失败原因），抛异常会
  破坏这条例行行为。
- **空收场守卫（evals/CLI 侧已有的 flag_empty_completion）就够了**：不足——
  守卫只能报「疑似上游故障」，根因文案（额度不足/鉴权失败/服务繁忙）
  全在中间件分类里，事件流补 error 才能把具体原因带给调用方。

## 代价

- `stream_agent_events` 多一处状态跟踪（fallback_text 及清除语义）；custom
  事件与 model_end 双信号以 custom 事件为准（真实路径唯一可达信号）。
- 生产 SSE 行为不变（custom 事件先到、合成 error 幂等跳过），但多一条
  无效事件经过桥接层（早退，无输出）。

## 验证

- 单测：custom 事件路径与 model_end 标记路径均 error 收尾、降级后成功
  输出恢复 stop、正常 run 不受影响（`tests/test_runtime_stream_filter.py`
  新增 3 例）。
- 实测：CLI `-p` 指向死端口模拟网关故障 → `__tw_error__`「服务暂时不可用」
  + `finish_reason=error` + 退出码 1（修复前：空完成 + stop）；正常端点
  回归 → 正确回答 + stop。
- 受影响面回归：stream filter / LLM 错误中间件 / SSE 桥接契约 / 工具失败 /
  记忆评测 / CLI 契约 / 记忆文件层与 backend 共 179 passed，改动文件 ruff 干净。
