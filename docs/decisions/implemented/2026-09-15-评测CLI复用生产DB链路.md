# 决策：评测 CLI 的 super 跑次复用生产 headless 入口（DB 持久化 + 生产 SSE）

状态：implemented
日期：2026-09-15

## 问题

评测 CLI（`noesis chat -p`）此前是「第二条集成路径」的残留：`db=None` 直调
`run_agent` + MemorySaver + env 直连模型快照 + 自研 stream-json 采集。后果是
评测会话在 DB 里只有空壳（177 个会话 0 条消息）、子 Agent token 完全不可见
（对照 Codex 时只能靠估算）、每换一次事件词表就要重写一遍采集/查看器适配。
评测想要的观测性（消息、run 生命周期、token、工具轨迹）生产链路本来就全部
落库，再在 CLI 侧手拼一套属于重复建设。

## 决策

CLI 不经 HTTP，但其余全部复用生产件，super 的 `-p` 跑次收敛为单一实现：

- 入口复用 `run_channel_agent`（channel_run_service）：会话行、用户消息
  SSOT、`TAgentRun`（owner 预写不被 dispatcher 抢）、run_manager 检查点与
  终态落库全部走生产路径；新增 `run_id`/`model_id` 透传参数供 CLI 预订阅
  与显式指定模型。
- 事件流复用 `run_manager.subscribe` + `encode_sequenced_event`：CLI
  stdout 即生产 SSE 同源词表（raw 底账 = 可重放 SSE 流）；终值 record 以
  `ChannelRunResult` + `RunCompleted` 载荷组装（DB 权威），不从流式文本
  重新拼接。
- checkpointer 换 `init_checkpointer()`（Postgres，同 server lifespan），
  MemorySaver 直连路径在 super `-p` 下删除；交互模式与 common/simple_mcp
  的 `-p` 维持直连路径（生产 headless 入口本就只覆盖 SuperAgent）。
- 模型解析回归生产语义：`--model` 传内置目录 id 或评测账号的自定义模型
  复合 id（如 `huoshan/glm-5.3-flash`，测试账号已有火山 Provider 现成条目），
  env 直连（`NOESIS_API_KEY`/`NOESIS_BASE_URL`）不再用于 super。
- CLI 进程补三件 server lifespan 等价物：`capture_main_loop()`（否则子
  Agent executor 的 DB 落库经 `run_on_main_loop` 全部静默跳过——实测子
  run 永远 queued、子会话 assistant 消息空骨架）、Langfuse 退出 flush
  （短命进程不 flush 则 trace 丢失）、`wire_langfuse` 自动补 backend
  sys.path（console script 不含 cwd，`import server` 失败曾被静默吞掉）。
- driver（cli_driver）super 单路径：终值取 `__tw_result__`、工具调用从
  SSE 载荷提取、`stats-update` 末帧的 `uncached_input_tokens` 即含子
  Agent 的全 session 真实计费口径；旧 stream-json 采集分支与 env 直连
  注入删除（所有评测线经 driver 均为 super）。viewer 与 `--recollect`
  同为单一 SSE 词表：viewer 只解析 SSE 帧，recollect 只取 `__tw_result__`
  行（driver 层采集故障的零成本恢复入口）。

## 备选方案

- **继续 env 直连 + MemorySaver（维持现状）**：否——`_resolve_model_for_query`
  开头就清空运行时快照，env 直连与生产解析路径天然冲突；且观测性缺口
  （子 Agent token 黑洞）无法在该架构下补齐。
- **评测走 HTTP（打真实后端）**：否——沿 2026-08-08 职责边界结论，且进程
  隔离与逐题环境注入（超时、子 Agent 窗口）在 HTTP 面没有对应旋钮。
- **observation bus / JSONL 作为一等观测载体**：否——等于再造一个 DB；
  raw jsonl 降级为可重放底账与 DB 不可达时的兜底。

## 后果与代价

- super `-p` 硬依赖本地 PostgreSQL（Postgres checkpointer + 落库）；
  无 DB 的独立安装场景只剩交互模式与非 super `-p`。
- 超时杀进程时 DB run 行可能遗留 running（SIGKILL 无收口），下次 server
  启动由既有对账收口；评测记录仍以 timeout 判失败。
- 模型名从 env 值改为 DB 复合 id，评测命令的 `--model-id` 口径变化
  （deepresearch/记忆线帮助文本已同步）。

## 验证

- 冒烟：DeepResearch id=20 经 DB 跑次出 16,306 字报告（1671s），主 run
  completed/stop、assistant 消息 13 parts、usage 94.6K/16.5K token、
  3 条 model_calls 落库；viewer 双格式解析、5 工具全带输出。
- 子 Agent 修复后验证：子 run completed/stop、子 assistant 消息 29 parts、
  77K/3.5K token 与 6 条 model_calls 进库；`stats-update` 末帧
  uncached 402,910 = 主+子真实计费口径。
- Langfuse：直接 shell 跑 CLI 出 `LangGraph` trace（session 前缀可见）。
