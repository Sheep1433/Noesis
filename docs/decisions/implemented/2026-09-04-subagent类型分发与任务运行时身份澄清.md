# 决策：subagent 类型分发走自建注册表与中间件，执行器保持类型无关

状态：implemented
日期：2026-09-04

## 问题

`start_task` 只有单一隐式子 Agent 种类：worker 配方硬编码在 SuperAgent 装配层，无类型参数、无分发点，增加种类只能复制装配代码。同时任务身份只存在于消息历史，上下文压缩后模型可能丢失任务清单；执行器名为 `BackgroundSubagentExecutor` 却承载 subagent / shell 双 kind，命名与语义错位。

## 决策

- **三层分工**：`SubagentRole` 注册表（类型名 → 编译配方声明）承担声明面；`NoesisSubagentMiddleware` 承担工具面（五个工具收编、`subagent_type` 必填、类型清单注入 system prompt）与任务身份 graph state（`bg_tasks`，Command 写入，随 checkpoint 持久化、免疫压缩）；`BackgroundTaskExecutor`（改名）继续承担生命周期，**不感知类型**——启动前由中间件把角色解析成 worker_factory 注入。
- **模型绑定在配置层**：`SubagentRole.model_id` 声明类型专属模型，未绑定沿用父 Agent 模型；`start_task` 不暴露模型参数——运行时只选类型不选模型。生效模型随版本化 descriptor（`extra["subagent"] = {version, type, model}`）落 child session，供重启重建取配方。
- **state 是投影不是真相源**：`bg_tasks` 只存身份与快照，任务状态与结果永远实时查执行器（miss 落 DB），终态条目保留不删。

## 备选方案

- **复用 deepagents `AsyncSubAgentMiddleware` 形态**：其执行边界是远程 Agent Protocol 客户端，与本进程隔离 loop 模型冲突——套壳即引入第二套执行语义。采纳其声明面形状（spec 字段、Command 写 state、prompt 注入），执行面归自有 executor。
- **拆分 subagent / shell 两个执行器**：会复制状态机、协作停止、终态单一收口这套全仓不变量密度最高的代码，是代价最差的重复。双 kind 维持单执行器，差异经注入携带；kind 分支收敛的触发线定为出现第三种 kind。
- **任务身份持久化走 DB 新表**：曾有 `t_bg_task` 表，已退役。任务清单的产品数据由标准 child session/run 承载；graph state 投影只解决「模型压缩后失忆」，不需要第二个事实源。

## 代价

- `subagent_type` 必填：模型侧 schema 缺参即拒，存量调用该工具的提示词需模型按类型清单表态（类型清单已注入 system prompt）；历史 child session 无 descriptor 不回填（无消费路径）。
- 工具返回值改 `Command`：仅 `start_task` 一处（身份写入点），check/cancel/send/list 维持纯文本，控制桥接层兼容面。
