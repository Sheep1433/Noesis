# 决策：openspec 主规格收缩治理（2026-09-03 轮）

状态：implemented
日期：2026-09-03

## 问题

主规格积累了两类债：其一，4 个已实施完成的 change 长期未归档，delta 未落主规格，spec 停留在旧代际（`agent-background-tasks` 甚至带着归档残留的 `## ADDED Requirements` 标题与 `TBD` Purpose，`openspec validate` 常红）；其二，仓库经历「服务层下沉 noesis-core、late-context 被动注入删除、md 记忆层取代 cortex、`server` 壳更名」多轮架构演进后，多份 spec 仍描述退役方案——`agent-runtime` 的记忆注入条目与现行「无被动注入、search_memory 主动召回」直接矛盾，`offline-evals` 约 135 行 memory 评测 Requirement 全是 cortex 设计（Bulletin/capture-extraction-consolidation/release gate），`agent-harness` 与 `user-platform` 引用的 `noesis_server.*`、`packages/harness` 路径已不存在，`agent-tool-failure-handling` 的错误短句表与代码现行表不一致。

## 决策

1. **先归档后收缩**：unify-run-delivery / research-source-provenance / repo-constraint-centralization 三个全绿 change 的 delta 手工落主规格后归档（`--skip-specs`；CLI 自动应用会拿不同代际的 delta 互相覆盖——两 change 交叉 MODIFY `agent-background-tasks` 的同一 Requirement，须手工合并为一份现行文本）。`tool-context-append-only` 剩 1 项用户人工验收任务，保持活跃。
2. **删改以代码实证为准，不按文件新旧**：每处删改先 grep 实现存在性（例：`late_context.py` 已删、`_CATEGORY_TEXTS` 短句表、`test_core_package_boundary.py` 边界、`evals/agent/memory` 应召回评测）。删除：offline-evals 旧 cortex 评测节、user-settings Bulletin 残留、agent-runtime 旧被动注入条目；重写：agent-harness（现行 `noesis` 内核包 + `server` 薄壳单向依赖）、agent-tool-failure-handling（现行锚点 `noesis.errors.tool_failure` / `noesis.chat.tool_state`，删除逐场景验收矩阵目录——语义保留在 Requirement，测试在 `backend/tests`）、user-platform 路径；改名：`agent-memory-cortex` → `agent-memory`（id 是死方案残留，内容是现行 md 记忆层）。
3. **能力数 15 → 16（登记补录）**：收缩的是过时内容（总行数 4100 → 4008，其中 delta 落入净增约 300 行现行内容），不是模块数。`agent-memory`、`agent-background-tasks`、`repo-collaboration` 三个未登记能力补进 README 与 config.yaml 能力清单。
4. **SSE 事件词汇按实现写，不按提案写**：unify-run-delivery delta 提出的 `run.started` / `approval.required` / `approval.resumed` 未按提案名实现（线上为 `hitl-required` + `run.finished`，旧 `finish`/`abort` 仅存于 CaseCoordinator 隔离适配），主规格按代码现实记载并指向 `docs/engineering/platform/chat-streaming.md` §4.2b 权威清单。

## 备选方案

- **把 13+ 模块大规模合并为 5 个大域 spec（聊天/Agent/KB/用户部署/评测）**：否决。config.yaml 既有规则已约束「避免再拆过细的能力 id」，现有粒度与 4 个 in-flight change 的 delta 引用（platform-chat / agent-delivery / agent-runtime / container-deployment）兼容；合并会迫使在途 delta 全部改路径，收益仅文件数下降。
- **按 git 时间戳/归档批次判断 spec 新旧**：否决。`agent-memory-cortex` 文件名指向死方案但内容是现行规格（md-memory-layer 归档时写入了旧 capability id），逐项代码核对是唯一可靠判据。
- **保留 agent-tool-failure-handling 的 S-/E-/N-/T-/P-/F-/A- 场景目录作为验收矩阵**：否决。矩阵引用的函数（`parse_tool_outcome`、`format_user_tool_output`、`PROCESS_TOOL_NAMES`、`AioSandboxBackend`）已不存在，逐行校正成本高于语义价值；对应测试仍在 `backend/tests/test_tool_failure*.py`。
- **删除 `repo-collaboration` 而非登记**（它是仓库流程而非产品能力）：否决。其 delta 含可验收 Requirement 且由 CI gate 钉住，丢弃等于让 repo-constraint-centralization 的成果失去 spec 记录。

## 代价与遗留

- `agent-background-tasks` 的「单工具同异步参数」「协作式停止」等条目源自 super-agent-async-tasks 归档时的 delta 原文，本轮仅做结构修复（去 ADDED 标题、补 Purpose），未逐条复核其与 executor 现实的偏差——留给下次触碰该能力时处理。
- docs/bug/ 中历史排障记录引用 `noesis_server` 旧路径，属带日期的事故日志，不改写。
- spec 总量仍偏大（platform-chat 732 行、agent-delivery 658 行）；进一步收缩依赖把「与代码对齐已由契约测试钉住的细节」下放到 `docs/engineering/`，需逐能力评估，未纳入本轮。
