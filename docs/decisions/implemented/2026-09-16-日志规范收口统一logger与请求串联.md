# 决策：日志规范收口——统一 logger 补齐豁免清单、request_id 串联、SQL 回显默认关

状态：implemented
日期：2026-09-16

## 问题

日志审计发现四类漂移，各有不同根因：

1. **服务端业务代码绕过统一 logger**：`session_stats_middleware` 和
   `user_llm_service` 用标准库 `logging.getLogger`。标准库 logger 在服务进程里
   没配 handler，输出走 Python lastResort——只出 WARNING 以上、裸打 stderr、
   不进 `.noesis/logs/` 轮转文件，等于这些日志实际不可查。
2. **日志文件名与内容矛盾**：唯一文件 sink 叫 `{日期}_error.log`，但级别设的
   是 `resolve_log_level()`（dev 下 DEBUG），文件里 90% 是非 error 内容。排查
   时会默认"这文件里只有错误"，误导定位。
3. **日志无法按请求关联**：一条 SSE 链路会产生几十条日志，此前只能靠时间戳
   人肉对齐。
4. **SQL 回显默认开**：`yaml_config.py` 内置默认 `db.echo=True`，而本地不存在
   `backend/config.yaml`（走内置默认），每条 SQL 直接打 stdout 与业务日志混流。
   CLI 早已专门设 `DB_ECHO=false` 防 stdout 污染，服务端却没人关。prod 三份
   配置样例都显式写 `echo: false`，与内置默认互相矛盾。

## 决策

- 两处标准库 logger 换成 `noesis.runtime.logging`（`exc_info=True` 同步改
  `logger.opt(exception=True)`，`%s` 惰性格式化改 loguru `{}` 风格）。
- 文件名改 `{日期}_noesis.log`，诚实反映"全量日志"定位。
- `runtime/logging.py` 格式加 `request_id` 槽位（默认 `-`）；新增
  `server/middleware/request_log_context.py`，HTTP 请求经
  `logger.contextualize()`（contextvars 实现）绑定，复用入站
  `X-Request-ID` 或生成 12 位短 ID，响应头回传。业务代码不需要手动传递。
- `db.echo` 内置默认翻转为 `False`，`config.example.yaml` 对齐并加注释。
- `backend/AGENTS.md` 规范补三条既定豁免，避免后续审计反复误报：
  deepdoc（RagFlow vendored）、noesis-cli（stdout 是 JSON/流式契约，标准库
  日志定向 stderr）、`config/env.py`（唯一绕过点，代码内有注释说明）。

## 备选方案

- **按请求/业务拆分多个日志文件**：排查需求已被 Postgres（消息/run 权威
  记录）和 Langfuse（调用链）覆盖，`.noesis/logs/` 只需承担"异常往哪看"。
  单体进程拆多文件后，查一个时间点要跨文件对时间戳，成本反升。多实例部署
  需要分流时再议。
- **把 `config/env.py` 的 loguru 直取改回统一入口**：`runtime/logging` 依赖
  `config/paths`，config 是最底层，从 env.py 导入 runtime.logging 会倒置依赖
  并让 sink 初始化提前到配置加载期。loguru logger 是进程级单例，直取与统一
  入口是同一对象，保留例外并文档化是更诚实的处理。
- **`__main__` 测试块 print 豁免**：`simple_mcp.py` 是业务包里唯一真 print，
  数量少，统一改掉比维护"测试块例外"规则便宜。

## 代价

- 日志文件名变更后，旧 `{日期}_error.log` 仍留在 `.noesis/logs/`，跨日期
  排障时新旧文件并存一段时间；按日期排序仍连续，不做迁移。
- 旧日志没有 request_id 槽位，格式统一只对新生效；现有基于日志的脚本若
  按行解析格式需同步（当前无已知消费方）。
- request_id 中间件对每个 HTTP 请求多一次 uuid 生成与 header 读写，量级
  可忽略。
