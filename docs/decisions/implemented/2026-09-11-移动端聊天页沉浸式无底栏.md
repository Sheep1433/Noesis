# 决策：移动端聊天页沉浸式——隐藏底部导航栏

状态：implemented
日期：2026-09-11

## 问题

移动端底部导航栏（对话/知识库/扩展/设置）此前在所有页面常驻，包括聊天页。聊天页底部本就有输入条，再叠一条 56px 固定底栏，输入区被抬高、消息可视高度变小，两个底部控件并存重心混乱。产品页（知识库、扩展、设置）之间是平级切换关系，底栏合理；聊天页是工作界面，应当全屏沉浸。

## 决策

- `shouldShowMobileBottomNav`（`frontend/src/config/navigation.ts`）收紧：聊天路由（ChatRoot/ChatIndex/ChatNew/ChatSession）一律不显示底栏；底栏只属于非聊天的产品页，KnowledgeBaseDetail 维持原有的隐藏。
- 壳层 `.app-shell__main--mobile-chat` 底部 padding 从「底栏高 + safe-area」改为 0，聊天内容画到物理底部；输入条 `.chat-input-footer-bar` 在移动端加 `padding-bottom: var(--noesis-safe-area-bottom)`，用自身背景盖住安全区，避免露出壳层背景色带（聊天内容背景与壳层背景不同色）。
- 锚在 `.chat-main-inner` 底缘的回到底部按钮同步加 safe-area 补偿，保持与输入条的相对间距不变。
- 聊天页内的跨页面导航由既有历史抽屉承担（抽屉底部已有知识库/扩展/设置入口），用户不会被困在聊天页；产品页底栏上的「对话」入口负责返回聊天。

## 备选方案

- **键盘弹起时才隐藏底栏**：只解决输入时的遮挡，不解决常驻 56px 的空间占用，且键盘显隐切换时底栏闪进闪出。否。
- **聊天页复用 `--mobile-no-nav` 的通用留白 padding**（同 KnowledgeBaseDetail）：实现最省，但聊天内容背景与壳层背景不同色，输入条下方会露出一条异色带，还得再补背景修补，不如让内容直接画到底。否。

## 后果与代价

- 聊天页与产品页的导航模型不再对称：产品页之间靠底栏切换，聊天页靠历史抽屉离开。后续新增顶层产品页需同步两处入口（`mobileProductNavItems` 与历史抽屉的 `mobileHistoryNavItems`）。
- 小屏聊天页多出约 48px（底栏高 − 输入条新增 safe-area 留白）的消息可视高度；无 home indicator 的设备上输入条贴到屏幕底缘，间距由输入条自身 8px padding 保证。
