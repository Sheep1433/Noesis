# 决策：压缩上下文契约与摘要事实原子性

状态：implemented
日期：2026-09-11

## 问题

多 fixture 评测（cc-0146daeb / cc-03cf390f / cc-1b34e49d，各 20 题 × 3 组）
暴露两个行为层问题，与摘要质量无关：

1. **模型不知道自己有什么、缺什么。** 压缩后的上下文只是一条摘要，没有任何
   声明告诉模型「上下文由什么构成、哪些类别的内容被遮蔽了、缺的东西从哪恢复」。
   症状：闭卷组在答案就在上下文里时仍空转工具（16/20 题有工具活动，多道满分
   题烧 30 万 token 挖沙箱）；检索组在可答对的题上被工具循环带偏——三份
   fixture 逐题对比，检索明确救回 8 题、同时反降 7 题，净收益归零。
2. **摘要叙述合并稀释信息。** 丢分题集中在「用户追问 → AI 给出解释/复盘」类
   内容（"AI 给出的核心解释""复盘后认定的误导源"）——八节摘要把这类问答
   压成叙述句，多个事实合并导致要点丢失。

完成口径（剔除 9 个网关故障回合）下，压缩闭卷三份平均约 66%，不压缩约 82%
——压缩仍有约 16 个百分点的真实损失；原话装回改造（35% → 66%）大幅有效
但非无损。

## 决策

1. **上下文契约（`_CONTEXT_CONTRACT`）**：压缩摘要消息的头部由一句
   "Here is a summary…" 升级为自描述契约——上下文构成（摘要 + 用户原话
   + 最近若干轮原文）、按类别声明的盲区（早期工具输出原文、AI 回复原文与
   解释细节、精确数值与命令原文）、使用原则（先上下文作答；确信属于被遮
   蔫类别才定向检索；都没有就明确说明缺失，不翻文件系统、不猜测）。契约
   是静态脚手架：不携带会话特定信息，措辞与工具挂载无关（闭卷场景下模型
   被引导声明缺失而非乱翻），因此闭卷/检索两组同构、评测单变量链不变。
2. **摘要事实原子性**：指令的 bullet 规则收紧为「每条恰好一个原子事实——
   一次解释、一个结论、或一个决定及其理由；禁止把多个事实合并成叙述句」。

两处均为通用机制（按内容类别声明状态、按信息质量标准约束摘要），不针对
任何观测到的具体失分题。

## 备选方案

- **针对失分题类别打补丁**（加「问答对」节、给检索组单独写 prompt）：
  被否——按题目类别定制 prompt 是过拟合评测集，换 fixture 即失效。
- **契约注入为独立消息或 system prompt 前缀**：被否——独立消息进入
  checkpoint 会混入再压缩的摘要输入（机制语义被污染）；改 system_message
  会破坏稳定来源分区（Dynamic/Durable 注入的边界）。附着在摘要消息头部
  （Codex SUMMARY_PREFIX 同位）零机制侵入。
- **AI 消息关键内容也进装回**：被否——装回层职责是「用户原话」这一确定性
  兜底；AI 内容的重要性判断没有客观判据，纳入即引入无界成本，归摘要层。

## 代价

- 摘要消息头部约 300 字符的固定开销（每次模型调用都随上下文发送）。
- 契约声明「可能不在视野内」的类别是保守枚举，个别情况下相关内容其实在
  保留尾里——模型可能多一次不必要的检索。

## 验证

- 单测：契约内容专项（构成/盲区/恢复通道/闭卷约束逐项在场、静态无会话
  内容）+ 既有投影/装回测试适配新前缀；后端全量单测 1595 passed。
- 行为验证（待跑）：单 fixture current+recovery 对比，验收指标是检索
  净收益转正与闭卷工具空转回合数下降，不是单纯追分。
