# 决策：引用判定收紧为完整标记精确命中，工具供料去噪，报告文件预览编号（citation-supply-tightening）

状态：implemented
日期：2026-09-04

## 问题

research-source-provenance 落地后的引用归因包含三条通道：完整 `[citation:标题](ref)` 标记精确命中、残缺标记（无 ref 括号）host/标题宽容匹配、正文裸 URL canonical 兜底。后两条非标记通道造成两类实际缺陷：

1. **面板引用与正文上标脱节**：模型未按协议输出标记时（实测发生过），正文普通链接仍把来源升格为「引用」，面板显示「引用 M」分组与引用优先编号，正文却没有任何上标可对应——「正文 badge 序号与面板序号一一对应」的不变量失效（2026-09-04 用户报告并经代码定位）。
2. **工具供料噪音**：`web_search`/`web_fetch` 每条结果输出恒为 `citable: True` 的布尔字段，KB 工具输出 `citable` 门禁字段。引用的决定发生在模型输出阶段（prompt 约定），模型从不需要该字段；主流对照（Perplexity Agent API `search_results` 仅 `id/url/title/date/snippet`）均不向模型暴露资格标记字段。竞品调研另确认：Perplexity 官方文档明示「模型是否加标记取决于 prompt；无论有无标记，检索结果条目才是引用的事实来源」——面板不依赖标记、也不把裸 URL 升格为引用。
3. **文件交付断号**：深度研究报告写入 workspace 文件后，文件预览渲染引用标记时未传入弧引用索引，上标全部降级为无编号「·」形；KB 徽章点击无响应——报告内引用与来源面板编号无法对应。

## 决策

openspec 变更 `citation-supply-tightening`：

1. **引用判定单通道**：弧面板引用子集只认归因文本（交付正文 + 弧内写入文件内容）中完整标记的 ref 精确命中（web 按 canonical URL、KB 按 kb ref）；删除裸 URL 兜底与残缺标记宽容匹配。归因文本无完整标记时面板降级为仅「共检索 N」。保留引用优先编号与「引用 M · 共检索 N」分组两项增强（2026-09-04 用户裁决：合理增强，非自创偏离）。
2. **工具供料去噪**：web 工具结果不再注入 `citable`；KB 工具结果不再输出 `citable`，`citation_ref` 仅对具稳定版本身份（document/version/segment 齐全）的命中输出——无身份命中按 prompt 约定自然不引用，注册层 `EvidenceEnvelope` 身份校验亦拒收，供料与登记两侧对「可引用」收敛为同一判定。
3. **注册门禁收敛**：`message_builder` 删除 `citable` 布尔过滤（与 envelope 校验本就冗余），拒收统一走 `invalid_evidence_envelope` 可观测路径。
4. **报告文件预览编号**：弧面板数据携带 write_file/edit_file 写入路径；chat 页构建「归一化路径 → 弧引用索引」映射（同文件多弧写入取最近的弧，后写覆盖），文件预览按所属弧编号渲染上标；KB 徽章点击跳转对应 Collection 文档路由（与聊天消息内行为一致）。无所属弧的文件保持无编号渲染。

## 备选方案

- **保留裸 URL 兜底、渲染层在 URL 出现处补插上标**：可让兜底命中也有正文痕迹，但触碰「平台 SHALL NOT 改写模型正文」边界，且插入位置与语义归属不确定，否。
- **服务端算法归因（Gemini 式 claim-to-source binding）**：既有决策已否，本变更不推翻；完整标记 + 确定性匹配的路线保持。
- **`citable` 仅从模型侧隐藏、注册层继续消费**：工具输出是单工件双消费（模型上下文 + retrieval part 解析），无独立通道可拆分；且注册过滤与 envelope 校验冗余，保留属死代码，否。
- **对齐 Perplexity 放弃分组/改检索序编号**：2026-09-04 用户裁决保留分组与引用优先编号——比 Perplexity 多一层「报告建立在多少证据上」的信息，属合理增强。

## 代价与遗留

- 引用数字普遍变小：裸 URL 与残缺标记命中的来源不再计入「引用」，面板「引用 M」比变更前偏低。这是把「低估」换「误报」的语义修正；「共检索 N」不受影响。
- 模型不守协议（不写标记）时引用数为零：与 Perplexity 同代价，靠 prompt 约定缓解；不引入算法归因补数。
- KB 旧文档（legacy_unversioned）命中不再供 `citation_ref`：模型仍可基于其内容回答，只是无法引用——不可溯源不引用。
- 文件被弧外通道（MCP、手动编辑）写入引用标记不参与归因：范围与变更前一致（只认弧内 write_file/edit_file）。
- 子 Agent 嵌套正文仍不参与归因：主 Agent 复述交付的当前形态下成立；若出现子 Agent 直接交付形态需重议（research-source-provenance 已记录该边界）。
