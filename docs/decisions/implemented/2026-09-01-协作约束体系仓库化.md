# 决策：协作约束体系仓库化（skills 单一归属、审查经济学、写作卫生、决策记录、最小执法层）

状态：implemented
日期：2026-09-01

## 问题

对 coding Agent 的开发纪律约束分裂在两处：仓库内的 `AGENTS.md` / openspec / 少量仓库级 skill，和用户个人目录下的用户级 skill——其中被根 [AGENTS.md](../../../AGENTS.md)「代码质量 Skills」表**强制引用**的三个 skill（code-review、code-simplification、diagnosing-bugs）全部住在用户级目录。仓库是所有 Agent 实例（不同工具、全新环境、其他协作者）共同可见的最低公约数，强制流程住在仓库外意味着它只对「恰好装了这些 skill 的环境」生效。且 `.agents/` 目录当时被 gitignore——连已有的仓库级 skill 都从未进过版本管理，「仓库归属」名存实亡。

实测暴露的三类缺陷在既有体系内无防线：Agent 互审总能翻出大量低价值发现（机器已证明的属性被反复提及、blocker 与 nit 混排、被审方表演性认同）；注释与文档积累「会话视角残留」（"原先/后来改成/被 review 否决"类文字）成为过期注释；设计决策散落在 commit message、openspec 归档件与个人记忆中，被否方案无处可查，同一裁决被反复重新争论。

## 决策

建立五件套，全部仓库归属（OpenSpec change `repo-constraint-centralization`）：

1. **skill 单一归属**：强制引用的三个 skill 迁入 `.agents/skills/`（move 非副本），`.agents/` 解除 gitignore；[AGENTS.md](../../../AGENTS.md) 声明「仓库 skill 禁止在用户级保留同名副本」。
2. **审查经济学**并入 code-review：CI/gate 已证明的属性禁提、blocker 与 suggestion 分离、review 意见逐条技术性回应禁止表演性认同；同时并入语义消费者检验（新增持久字段/事件/API 必须回答「删掉它哪个已验证场景失败」）。
3. **写作卫生**新 skill `noesis-prose-hygiene`：六类会话视角残留 + 唯一检验（只能看到当前仓库的读者能否解析每个引用）+ 命题保真（事实性从句必须存活），报告制执行。
4. **决策记录体系** `docs/decisions/`：路径编码生命周期，implemented 必含备选方案节，非平凡改动同提交交付，新记录落档时做取代审计；openspec 归档时把 [design.md](../../../openspec/changes/repo-constraint-centralization/design.md) 的长期依据提炼为决策记录（归档件是变更期文档，随时间失去约束力）。原 `docs/NOTES.md` 决策卡片机械拆分后**整体归档**至 `archived/`（138 条，只读历史素材、不算现行权威、不参与校验），未带决策日期的工程记录归 `docs/engineering/legacy-worklog.md`。
5. **最小执法层**：`scripts/change-scope.py`（diff 影响面 + 分层 + owning checks，经济学的可执行前提）、`scripts/verify_md_links.py`（相对链接与锚点校验，执法「指向而非复述」）、`scripts/verify_decision_format.py`（决策记录格式校验，只查存在不查内容质量）进 CI。

## 备选方案

- **copy 而非 move 迁移**：用户级与仓库各留一份。否决：同名双份触发来源不定、修改必忘其一，等于允许两套约束并行漂移。
- **迁移时按 dsh/DeerFlow 模板整体重写三个 skill**：否决。经全文质量验证（2026-09-01），自有 skill 的骨架（两轴审查、行为保持契约、可证伪假设诊断环）质量达标且无外部对应物可替代；外部可借鉴的是纪律条款（经济学、语义消费者检验）而非整骨架，改造限于死引用清理、openspec 适配、示例瘦身与纪律并入。证据见 [dsh 调研](../../research/dsh-agent-collaboration.md)；同题 DeerFlow 调研已清理，其唯一采纳项（语义消费者检验）以本决策与 code-review skill 为权威记录。
- **决策记录引入 hash 冻结归档 + append-only manifest**（外部参照源的做法）：否决。该机制防的是多人并行政写历史快照；单人开发 + git 历史已提供同等保障，机制留待需要时引入。
- **`AGENTS.md` 字数预算 gate**：否决。当前无膨胀证据，出现膨胀再加（避免为不存在的问题建机制）。
- **JSON Schema 契约目录**（DeerFlow 路线）：否决。其收益依赖跨语言多消费方场景；Noesis 单仓库前后端，SSE/子 Agent 事件枚举漂移风险变大时再评估。
- **保留 `NOTES.md` 单文件继续累积**：否决。单文件无生命周期、无取代审计、无法被逐条链接与 supersede，正是「被否方案无处可查」问题的载体。

## 后果与代价

- 其他项目失去这三个通用工程 skill（用户级已删）；需要时在目标项目各自声明，各仓库维持单一归属。
- 138 条历史决策卡片整体归档、不做逐条整理（裁决：历史不增加维护负担）；现行判断依据只看新格式记录与各 owning 文档，历史素材仅按需搜索。
- 三个校验脚本引入维护成本；误报处置原则记录于 DeerFlow 调研的「豁免清单」模式（精确匹配 + SHA 钉死 + 过期 + 永不豁免 blocker），首个 gate 出现实际误报时按该模式设计豁免机制，不提前建。
- 审查经济学与写作卫生对产出质量的改善需在 research-harness 等多 Agent 协作场景中观察验证。
