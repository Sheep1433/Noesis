# 决策：配置面收敛——删除 legacy 环境变量覆盖层，产品常量归位代码

状态：implemented
日期：2026-09-17

## 问题

配置面审计发现三类问题：

1. **双层冗余**：`env.py` 存在一整层 legacy 环境变量（36 处 `_legacy_env_*`，
   语义为"env 设了就覆盖 yaml"），58 个变量与 yaml 完全重叠。同一旋钮两个
   配置面，测试与文档都要双份维护，是配置面膨胀的主因。
2. **死配置**：governor 全组（6 个字段，防打转中间件已在前序重构中移除，
   配置面残留）与 `memory.index_max_lines/index_max_bytes`（消费方消失）
   无任何代码读取。
3. **产品常量误入配置**：检索证据登记上限（retrieval_limits 5 项）、历史
   检索输出预算（history_search 4 项）、附件注入管线参数（4 项）、记忆文本
   预算（3 项）——这些是纯算法参数，任何部署答案都相同，且原实现被迫加
   `ge/le` 边界防止"配置了不该配的值"，恰恰证明它们不该是配置。

## 决策

- 删除 `_legacy_env*` 覆盖层：所有 build 函数直读 yaml；**env 只保留
  密钥与部署身份类**（`EnvSecrets`：各类 API key、数据库密码、
  `APP_ENV`、分布式 Run 总线选择三件套）。docker 样例中两个 pydantic
  静默忽略的死键（`selection_model`、`inject_budget_tokens`）一并清除。
- governor 配置组整体删除（连同旧收敛测试改写为「已移除」断言）。
- 产品常量归位到唯一消费模块并附依据注释：
  `message_builder.py`（RETRIEVAL_MAX_* 5 项）、`history_search.py`
  （MAX_HITS/MAX_EXCERPT_CHARS/MAX_TOTAL_CHARS/MAX_WINDOW）、
  `input_resolver.py`（TINY_INLINE_CHARS/IMAGE_INJECT_MAX_EDGE）、
  `chat_attachment_tools.py`（READ_PAGE_LINES）、
  `chat_attachment_service.py`（PREVIEW_CHARS）、
  `memory_tools.py`（STALE_WARNING_DAYS）、
  `extraction.py`（MAX_ENTRY_CHARS/MAX_MESSAGE_CHARS）。
- 三份 example yaml 同步删除对应键；依赖 env 开关的沙箱/记忆测试改为
  直接替换 `GetConfig.get_sandbox_config` 或模块常量。
- [backend/AGENTS.md](../../../backend/AGENTS.md) 规范由「禁止硬编码配置」细化为：「配置只收环境
  参数；产品逻辑常量留在代码并附依据注释；判断技巧——两个部署理应
  相同的值不是配置」。
- 浏览器整文件文本通道（工作区预览/编辑、skill 文件编辑、用户记忆双
  文件写入）统一提至 5MB：约束方是访问者浏览器而非部署环境，
  原各自为 512KB 且命名 `_error.log` 式误导（文件名不叫 error 却记全量
  的同类问题）。报错文案同步 MB 化。
- review 补漏：`user_settings_api.py` 的记忆条目编辑接口也消费
  `max_entry_chars`（首版归位清单遗漏，review 抓到 AttributeError 风险），
  改为引用 `extraction.MAX_ENTRY_CHARS`。
- 评测进程约定改由配置层承载：`noesis.config.env._EVALS_PROCESS` 识别
  评测 CLI 子进程，沙箱强制 local_shell、模型超时放宽至 max(配置值,
  600s/300s)——替代被删除的 `SANDBOX_BACKEND`/`REQUEST_TIMEOUT`/
  `STREAM_IDLE_TIMEOUT` env 写入（`cli_driver`/`deepresearch/__main__`），
  语义不变（2026-09-08 决策的「评测不产生 runner 容器」保持有效）。
- 服务器 `deploy/config.docker.yaml` 同步清理死键（loop_detection/
  tool_call_limit/retrieval_limits/附件 3 键）。注意：生产曾把
  retrieval excerpt 预算调紧到 2000 字符/8192 字节，收敛后统一回仓库
  基线 8000/32768——生产检索清单条目会比此前更宽。

## 备选方案

- **保留 legacy env 层并标记 deprecated**：无人使用（部署面只有本机与
  docker compose 样例），过渡期只会延长双份维护成本，直接删除。
- **保留 governor 配置待未来重建防打转**：死配置挂十年也不会让功能复活；
  真要重建时按新设计重新提案，比考古旧字段更可靠。
- **把 max_output_bytes / run 时长等一并常量化**：这些与运维容量、模型
  速度相关，属真实环境参数，保持配置。

## 代价

- 曾用这些环境变量做覆盖的部署升级后设置会失效（当前无此类部署）；
  值的调整入口统一收敛到 config.yaml 与代码常量两处。
- 测试从"改环境变量 + 清缓存"改为"替换配置读取方法"，与生产读取路径
  的耦合从 env 转移到 GetConfig 单例，后者本身是既有结构。
