# 决策：Agent E2E 评测切 HTTP 生产路径并接入 ERB 官方判分闭环

状态：implemented
日期：2026-09-18

## 问题

Agent E2E 评测线（`evals.agent.rag`）原为进程内驱动 GeneralQAAgent + 自研判分（三档 judge / 引用三指标 / 失败归因），存在三个问题：①自研判分指标无外部认可度，RAGAS 试点又被引用归因措辞击穿（recall=0）；②评测会话以伪用户对象运行，业务库零落库，前端不可见也不可查证；③自研 runner 维护负担与评测目标（对外可辩护的数字）不匹配。

## 决策

1. **被测驱动切 HTTP 生产路径**：runner 重写为纯 HTTP 客户端——登录（cookie+CSRF）→ 建会话 → `POST /runs`（COMMON_QA + kb_collections 限定 + 关联网）→ 消费 `/runs/{id}/stream` 生产 SSE → 轮询读 DB 权威 assistant 消息。会话/消息/工具调用全部由 server 持久化，`--eval-user` 账号（默认 test）前端可见。
2. **质量指标全部换 ERB 官方口径**：删除自研三档判卷、引用三指标与失败归因模块，判分 prompt 与指标算法逐行取自 EnterpriseRAG-Bench 官方仓库（commit `d36685e` 锁定，判分脚本移植进 `erb_scorer/`，语料不入库可按 README 重建）。runner 只自动导出官方格式 `erb_answers.jsonl`（`question_id / answer / document_ids`，document_ids 从回答引用标记解析回官方 dsid）。
3. **document_ids 语义定为引用层**：HTTP 路径下 SSE 工具输出是渲染摘要不含文件名，检索全量文档不可得；提交"回答实际引用的文档"——召回指标变为引用层金标覆盖，与检索层口径不可比，需随数声明。
4. **配套**：题池扩充（语料 532→566 篇 + 20 道 Conflicting Info 陷阱题，`erb-e2e-100.jsonl` = 冲突 20 + 常规 60 + 拒答 20）；`cli_driver` 增加 qa_type/kb_collections/web_search 透传（super 路径不受影响）。

## 备选方案

- **CLI 子进程 + headless 持久化**：实测 COMMON_QA 未迁移到 RunService typed 事件路径（producer 对 common 抛 TypeError「emitted SSE string」），headless common 无持久化是产品现状；补齐属产品级迁移，非评测侧可解，否决。
- **评测 harness 自行写库**（ChatService.build_session + save_message）：已实现并验证过，但会话缺工具调用与检索 parts，前端显示"已中断/信息不全"，且把产品持久化职责复刻进评测脚本，否决。
- **保留自研三档判卷作为补充**：判分语义与官方 Correctness 重叠、partial 折半口径需自行辩护，维护双口径成本大于收益，否决（judge.py 保留供 memory 线使用）。

## 代价

- 联网开关不可控：`QaQueryRequest` 无 web_search 字段，HTTP 路径联网行为由平台配置决定，评测请求无法显式关闭（进程内版可以）。
- document_ids 只含引用层：Document Recall 度量"引用了金标没有"而非"检索到了金标没有"，检索层回归仍由 `evals.kb.erb` 线承担。
- 每题多一次 HTTP 会话创建与轮询开销；server 必须在运行。
- 被测模型须以「provider_slug/模型名」复合 id 传入（走 DB 解析），不再接受内置目录裸 id。
