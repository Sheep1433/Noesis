# 决策：文档可读性与语义一致性的约束方式（prose-standard skill、契约测试、openspec 目录约定）

状态：implemented
日期：2026-09-01

## 问题

两个遗留痛点：一是文档的**语义层一致性**无防线——链接死活已有 gate，但「文档说的事和代码做的事是否一致」仍靠自觉，且已发现活标本：根 [AGENTS.md](../../../AGENTS.md) 的 SSE 事件清单漂移（写着 `tool-call-start` 旧名与 `token-details`/`finish-step` 两个代码里已不存在的事件名，缺 `stats-update`、`hitl-required` 等一串实际发射的事件）。二是 **spec 等文档 AI 味重、难读**——推导过程上屏、大纲体、措辞同质化，此前的多次裁决（结论先行/现算态/表格只放可枚举事实）停留在口头约定，没有任何载体在写作时注入。

## 决策

四件落地：

1. **`noesis-prose-standard` skill**（写作时触发）：五条底线（结论先行、现算态、表格只放可枚举事实、嵌套 ≤2、加粗只标一级重点）+ AI 味症状清单（套话开场、结构机械感、措辞同质化、命题稀释、虚假权威，适配自用户的博客去 AI 味清单）+ 发现探针（grep/awk 命令）+ 终检（首句拼骨架、删句测试）。**探针只发现候选，判断靠语义**。
2. **code-review 第 6 节**：diff 中的 prose 是 blocking 审查面，按 prose-standard 审可读性、按 prose-hygiene 查残留。
3. **`openspec/AGENTS.md`**（子树 standing order）：提案门禁（备选方案对比 + 语义消费者说明，缺一即提案不合格）与归档提炼规则（`design.md` 长期依据 → 决策记录）。
4. **两个契约测试**（`backend/tests/test_doc_contract.py`）：SSE 事件词表从 `langgraph_bridge.py` 提取（直接字面量 + 守卫集），断言 `chat-streaming.md` §4.2b 全收录；`config.example.yaml` 与 `AppYamlConfig` 模型双向比对（示例含未知键即红；模型字段不进示例必须在豁免清单显式登记）。

附带修复：[AGENTS.md](../../../AGENTS.md) SSE 段退回索引角色（词表唯一权威在 [chat-streaming.md §4.2b](../../../docs/architecture/platform/chat-streaming.md)）；归档提炼规则落 `openspec/AGENTS.md`。

## 备选方案

- **可读性用 CI 脚本**（段落长度/嵌套深度做 gate）：否决。用户裁决：会误报（技术文档里 200 字的机制说明是健康的）。采 dsh 模式——探针发现候选、语义判断由 skill 承载，机器只管可判定的子集。
- **把提案门禁与归档提炼写进 openspec-* skill 本体**：否决。这些 skill 是通用工作流，服务多个项目与广大使用者；项目特有规则属于项目自身，落 `openspec/AGENTS.md` 保持工作流与项目约定的分层。
- **从源码生成文档目录**（生成式文档，漂移在源头消除）：暂缓。当前漂移面窄（事件词表 + 配置示例），契约测试更便宜；生成式留给更大的面（如 API 参考）。
- **SSE 事件名建常量模块**作为代码侧单一真相再生成文档：暂缓。bridge 源码提取模式已够稳（测试自带「提取为空」断言防提取模式漂移）；常量化是代码整洁议题，另行处理。

## 后果与代价

- 事件提取依赖 bridge 的 `_format_sse` 调用形态——发射方式重构时测试需同步；`test_sse_events_documented` 的提取为空断言是该风险的兜底。
- 配置豁免清单（14 项，均为有默认值的非常规配置）会随字段增加变长，每次登记都 reviewable——这是设计而非缺陷（可见的豁免优于静默的缺失）。
- prose-standard 的语义判断依赖 Agent 执行纪律，可读性的语义层效果待观察；机器探针与 review 条款是二、三道防线。
- `tool-call-start` 旧名保留在 projection 重放路径（历史事件兼容），新代码禁止发射——该约束已写入 §4.2b 文字。
