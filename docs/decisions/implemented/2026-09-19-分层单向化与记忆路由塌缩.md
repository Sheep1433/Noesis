# 决策：分层单向化与记忆路由塌缩

状态：implemented
日期：2026-09-19

## 问题

声明的分层 `API → Service → Domain/Agent` 只存在于文档，import 方向上没有强制。由此积累出三类结构性债务：

1. **`agents/backends/` 是四层混装**：纯路径域逻辑（`paths.py`）、协议装饰器（`agent_path.py`）、运行时实现（`docker_exec` / `local_shell` / `memory`）、服务编排（`sandbox_lifecycle` / `factory`）挤在一个包里；容器创建逻辑三处重复（异步 ensure、`docker_exec._ensure_sync` 自建同步版、destroy 各拼一遍 URL）；skills 只读策略在 docker / local 两模式下由不同层执行。
2. **`/memory` 路由背着一个 300 行的 `GuardedFilesystemBackend`**：宿主布局错位（两个根文件在用户数据根、条目在 `memory/` 子树）迫使它实现两层键映射、手写 grep/glob/ls、合成虚拟目录列表；写入白名单与 `paths.py` 的容器路径判定各自维护一套。顺带发现存量 bug：它返回的 grep match 用 `content` 键，而 deepagents 0.6.12 格式化层只读 `text`——agent 侧 grep 工具在 `/memory` 路由上一直 KeyError（单测只查 `.get("content")` 所以从未红过）。
3. **agents ↔ services 双向成环**：11 个 service 文件 import agents，8 个 agents 文件反向 import services（`chat_service ↔ super_agent/kernel`、`backends/memory → MemoryStore` 私有方法、`tools → services`）；端口接缝 `subagent_runtime_port` 已示范正确姿势，却放在 services 侧且只覆盖一个点。

## 决策

**依赖方向单向化 + 记忆路由塌缩，全部改动直接落在 dev。**

```
noesis/
├── paths.py                 # ← backends/paths.py 上移：坐标系常量 + 归一（全仓库共享，services 不再反向 import agents）
├── memory/                  # ← services/memory 下沉为领域包：store / types / extraction / consolidation
│   ├── policy.py            #   新增：可写白名单、条目命名规则（单一事实来源）
│   └── layout.py            #   新增：seed 根文件 + 老布局一次性搬迁（两根文件迁入 memory/ 子树）
├── agents/backends/
│   ├── memory_fs.py         # ← 新增：FilesystemBackend 子类，仅覆写 grep（正则-or-字面，match 键回归 text）
│   ├── factory.py           #   /memory 单路由挂裸 FS + worker 整体只读；不再有 GuardedFilesystemBackend
│   └── sandbox_lifecycle.py #   ensure/destroy/同步重建共用 sandbox_api_path 与响应解析（三份去重为一份）
├── agents/middlewares/
│   └── memory_write_middleware.py  # ← 新增：白名单门卫（索引/journal 只读）+ 条目写后索引同步
└── agents/background/ports.py      # ← services/subagent_runtime_port 归位（接口归消费方）
```

配套规则：

- **`/memory` 写入语义全部进 `MemoryWriteMiddleware`**（主 Agent 与同步子 Agent 栈各挂一份；worker 路由整体只读故不挂）：白名单外写入直接拒绝并回原因，条目写入成功后按 frontmatter 投影同步 `MEMORY.md` 索引行（调 `MemoryStore.sync_index_line` 公开方法）。upload 通道不经工具层中间件，白名单门卫在 `MemoryFilesystemBackend.upload_files` 执行（与旧 backend 对齐）。guardrails 的 HITL 审批门（`memory_write_when`）与路由表、中间件消费同一份 `noesis/memory/policy.py`。
- **数据布局收敛**：`/memory` 路由 = 用户 `memory/` 子树整目录；`get_user_agents_md_path`/`get_user_profile_md_path` 改指向子树内，四个消费方经 getter 自动跟随；`layout.ensure_user_memory_files` 启动时把老布局根文件搬入（新旧并存保留新位置）。
- **端口方向修正**：`ports.py` 归 agents，services 侧注册（`configure_session_ops_port(ChatService)`、`configure_continuation_port(schedule_maybe_continue)`、既有 `configure_service_port(SubagentSessionService)`）；super_agent 的四个子会话回调、kernel 的 `merge_session_extra`、settle 的续跑调度全部经端口，agents 包内 `from noesis.services` 归零。组合根 `services/runtime_ports.register_runtime_ports()`（server lifespan、evals bootstrap、CLI `enter_context` 三处调用）保证端口在首个请求/任务前就绪，漏配进程以 RuntimeError 快速失败。
- **`history_search` 归位 repositories**（agents 工具与 factory 消费 DB 检索属仓储层职责）。
- **import 方向门禁**：`scripts/check-import-direction.py`（纯标准库，CI docs-gates job 接入）钉五条规则：agents 不 import services；memory 领域包不 import agents/services；repositories 不 import agents/services；`noesis/paths.py` 不 import 任何 noesis 模块；backends 不 import background。唯一白名单：`sandbox_lifecycle` 经 background 门面稳定契约 `fail_session_shell_tasks` 的容器销毁连坐。

## 备选方案

- **services 拆独立 distribution 包**：否。单进程部署、单库，无部署形态收益；agents↔services 环不解开前物理上切不动。
- **`/memory` 只读策略用 CompositeBackend 子路由表达**（`/memory/MEMORY.md`、`/memory/journal/` 只读子路由）：否。composite 按最长前缀匹配后**剥整段路由前缀**——`/memory/preference/` 子路由会把 `preference/` 一并剥掉、路径畸变；根文件路由剥到 `/` 指向目录而非文件。子路由粒度在 composite 语义下走不通，策略只能进中间件。
- **保留 `GuardedFilesystemBackend` 只修 grep 键 bug**：否。宿主布局错位是其 80% 复杂度的根源，布局收敛后 read/write/edit/ls/glob/upload/download 全部可裸用 FilesystemBackend，只剩 grep 一处真实差异值得保留（正则语义与 `search_memory` 工具对齐，有测试钉住）。
- **容器销毁连坐上移到 services 层 teardown 编排器**：否。连坐是销毁的不变式（所有调用方依赖），放进每个调用方必然有人漏；`backends → background` 是 agents 包内同层依赖，不违反声明的分层，保留原地并入门禁白名单。
- **根文件留在用户数据根 + 符号链接进 memory/**：否。引入第二套映射机制，与要消灭的东西同构。

## 代价

- **行为变化一**：根文件整文件 `write_file` 从「静默读后整替换」变为「拒绝已存在文件、要求 read-then-edit」——对齐 deepagents 全域语义（write=新建 / edit=修改）与 ReadBeforeWrite 门卫；Agent 记忆更新指引本就是 edit_file。
- **行为变化二**：`/memory` 上 grep 工具从「必然 KeyError 报错」修复为正常返回（match 键 `content` → 规范 `text`）；拒绝文案从裸 `permission_denied` 改为带原因的中文提示（模型可自纠）。
- **存量数据迁移**：老用户的两个根文件在首次 `ensure_user_memory_files` 时搬入 `memory/` 子树；新旧并存保留新位置（老文件原地不动）。部署即生效，无手工步骤。
- **门禁白名单**：`sandbox_lifecycle` 的连坐 import 是唯一豁免，规则与理由写死在脚本内。
- **注册时序**：非 server 入口（evals/CLI）跑 Agent 前必须经 `register_runtime_ports()`，否则端口调用 RuntimeError——文案已指明原因。
