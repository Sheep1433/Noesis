# 决策：引用溯源评测线与自建失败归因下线

状态：implemented
日期：2026-09-26

## 问题

引用溯源评测线（`evals/agent/citation.py`，格式遵循率 / 逐引用正确率 / 事实可溯源三项指标）与自建失败归因（`evals/agent/rag/attribution.py`，检索没召回 / 工具异常 / 推理错三类）随 b8891561（修 channel 外键的提交）移除，共 526 行含测试。该提交说明未记录删除原因，且 `openspec/specs/offline-evals` 仍保留「引用溯源评测」SHALL 需求与归因报告条款——规格与实现漂移，需要裁决恢复还是确认下线。

## 决策

确认下线，规格同步收缩：

1. **不恢复 526 行**：下线动因是评测线实现质量未达预期，恢复等于把问题请回仓库；95% / 91% 定位为历史基线（该线产出），不作为当前回归口径。
2. **offline-evals 规格对齐现状**：删除「引用溯源评测」整条需求（三 Scenario）；「Agent E2E 判卷与失败归因」改为「Agent E2E 判卷」，归因条款改为官方指标交叉读数——Document Recall 未命中 = 检索问题，检索命中而判卷不采纳 = 生成问题，可结合 kb 线 raw.json 逐题联查，不依赖独立归因模块（与 `backend/evals/README.md` 既有口径一致）。
3. **已知缺口如实标注**：可点击引用是产品承诺，评测线下线后引用质量无自动化回归——链路静默失效（如中文文件名被 markdown 编码层百分号编码导致索引失配）只能靠用户反馈发现。若未来引用相关缺陷反复出现，重写一条高质量引用评测线是首选解法。

## 备选方案

- **从 b8891561^ 恢复**：实现质量是下线动因，恢复不解决问题。
- **立即重写高质量评测线**：当前阶段优先级不支撑；先以已知缺口形态记录，等缺陷信号触发。

## 代价

引用链路失去唯一的自动化回归手段；规格收缩后「引用格式遵循率」不再是被钉住的系统行为。
