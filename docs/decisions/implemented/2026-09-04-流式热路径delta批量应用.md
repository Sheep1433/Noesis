# 决策：chat 流式热路径 delta 批量应用与 reducer copy-on-write

状态：implemented
日期：2026-09-04

## 问题

chat 页每个 text/reasoning delta 直接触发整链全量重建：`appendTextDelta` / `appendReasoningDelta` 克隆全部 part、`syncLegacyFieldsFromParts` 重建整条消息 content 字符串、`conversationItems` 数组整体重建、snapshot watchEffect 再拷贝一次、MarkdownPreview 全量重解析 markdown。成本按 token 频率 × 消息体量计价——长 run（深度研究可流数万 delta）下 V8 堆随分配速率扩张，后台标签 GC 惰性且释放页不归还，实测渲染进程 11 天膨胀至 2.4GB（根因六项链路与发现路径见 [docs/bug/chat-stream-hotpath-memory-bloat.md](../../bug/chat-stream-hotpath-memory-bloat.md)）。

## 决策

两层修复，整链开销按 flush 频率（~10Hz）而非 token 频率计价：

1. **delta 批量应用**（`frontend/src/views/chat/streamDeltaBatcher.ts` + chat.vue 接入）：text/reasoning delta 进缓冲，100ms 定时或 128KB 待 flush 字符阈值触发单次 parts patch。顺序契约由调用方保证——结构性帧回调（snapshot / message-start / tool / retrieval / reasoning-end / hitl / finish / error）顶部先 flush，会话整体重置点 clear，新 run 开始前 flush。`<think>` 拆分开关（nativeReasoningSeen）在 push 时捕获进缓冲条目，flush 时不读共享标志，标志翻转不改变已缓冲 delta 的语义。
2. **reducer copy-on-write**（`messageParts.ts`）：`appendTextDelta` / `appendReasoningDelta` 只新建命中的尾部 part，其余 part 复用对象引用。Vue 代理缓存按 raw 对象命中，引用复用使未变更 part 的代理身份稳定，子组件不再随每 delta 整体重渲染。

等价性由测试钉住（`__tests__/streamDeltaBatcher.test.ts`、`__tests__/messageParts.test.ts`）：连续同签名 delta 合并应用与逐条应用产出相同 parts；`<think>` 标签在任意切分点分批应用与整段应用结果一致（合并不改变增量解析语义）；COW 不改变输入、未命中 part 引用恒等。

## 备选方案

- **rAF 批量 flush**：否决。切后台后 rAF 不触发而 SSE 仍在推流——正是膨胀的触发场景。必须用 setTimeout；后台 timer 节流（≥1s，隐藏 5 分钟后 ≥1min）只影响展示延迟，缓冲量由 128KB 阈值兜底同步强刷。
- **传输层缓冲**（useSSEStream 帧分发前攒批）：否决。useSSEStream 是共享传输层（主聊天与子 Agent 投影共用 `createFrameHandlerTable` 帧词汇），改分发时序影响所有消费者；缓冲是消费侧 UI 策略，应落在 chat.vue 消费端。
- **响应式全套改造**（conversationItems 改 shallowRef + 定点 triggerRef + 删 snapshot watchEffect）：否决（本轮）。4700 行 SFC 内深层赋值点需逐点排查，风险面远大于收益；批量应用后残余每 flush 开销已降为指针级数组拷贝。若后续 profiling 证明 flush 粒度仍有压力再评估。
- **syncLegacyFieldsFromParts 移出链路、content 改 computed 惰性求值**：否决。批量应用后它每 flush 只跑一次（原每 delta 一次），成本已摊薄到与 MarkdownPreview 重解析同阶；为此把 content 推导挪进子组件反而扩大改动面。

## 后果与代价

- 首字与尾字显示延迟至多 ~100ms（flush 间隔），远小于网络首 token 延迟，换整链开销降 1-2 个数量级。
- 顺序正确性依赖「结构性回调先 flush」的调用约定：新增触碰 parts 的 SSE 回调必须补 flush。缺漏的表现是内容乱序（易发现，非静默损坏），约定写在 batcher 模块文档与接入注释里。
- SubagentConversationView（子 Agent 抽屉）仍是逐 delta 应用，但共享 reducer 已 copy-on-write，其 part 克隆开销同步消除；若深度研究常开抽屉场景实测仍有压力，再接同一 batcher。
- 修复效果的浏览器端量化（同会话同操作对比 footprint 增速）留给使用侧验证：关标签重开测「每轮对话内存成本」，修复前后同流程对比。
