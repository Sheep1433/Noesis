# 决策：压缩摘要去输出上限，被压缩区用户原话装回最终请求

状态：implemented
日期：2026-09-06

## 问题

压缩评测（20 题分层，cc-0146daeb）暴露两个结构性损失面：

1. **摘要输出被请求层 8192 token 上限封顶**。这个上限不是信息预算设计，是对
   一次实测故障（745K 输入、不限输出时单次产出 27 万字符复读）的应急闸。但
   对照实验推翻了它的前提：同一模型（glm-5.3-flash）跑在 codex 上做压缩
   从未出现倾倒——codex 的摘要指令基调是「Be concise」，而我们当时的指令
   写着「Be as detailed as the output budget allows」，在超长输入上等于在
   邀请倾倒。实测摘要也从未顶到上限（约 7.8K 字符 ≈ 2K token），模型自我
   收笔，上限没有约束到任何东西。
2. **闭卷宏观召回只有 40%**，逐题归因发现约 6 个百分点是「最早话题弧在摘要
   里整弧丢失」——近因偏置是模型行为，不是产品设计能直接纠正的。codex 的
   对照给出了结构性解法：它把被压缩区全部用户消息原文按 20K token 预算
   装回压缩后上下文（`collect_user_messages` + `build_compacted_history`），
   用户说过的话不赌摘要，冒烟中「用户原话」题 codex 答对、我们闭卷答错，
   答对的依据正是被保留的用户消息原文。

## 决策

三件事，全部围绕「不信任摘要，结构兜底用户原话」：

1. **摘要输出不设上限**（`factory.py` 的 `max_tokens_override` 移除）。质量
   防线维持在校验层：最小体量 + 复读检测 + 重试（这层防的是网关 9 秒空返回
   一类故障，与上限无关）。
2. **摘要指令改 Codex 交接基调**：开头改为「CONTEXT CHECKPOINT COMPACTION /
   handoff summary for another model」，删掉「尽预算详尽」；保留八节结构；
   新增时间弧覆盖规则（跨多话题阶段的会话每阶段至少一行目标与结论，不得因
   久远省略早期阶段）；规则基调改为「concise and structured」。
3. **被压缩区用户原话装回**（`CompactionMiddleware._final_request`）：压缩后
   发给模型的最终请求 = [用户原话（预算内倒序装满、最旧截断、图片剥离）,
   summary, 保留尾 28 条]。注入只发生在请求边界——压缩机制（摘要输入、
   cutoff 算术、事件结构、再压缩语义）看到的仍是 [summary, *raw[cutoff:]]，
   raw 永远完整保留在 checkpoint，装回是从原文幂等提取。预算走配置
   `summarization.user_message_tokens`（默认 20000，对齐 codex
   `COMPACT_USER_MESSAGE_MAX_TOKENS`；0 = 关闭）。

## 备选方案

- **保留固定上限、只调大数值**：实测上限从未被顶满，调大不改变模型 ~2K
  自我收笔的行为，纯装饰。
- **指令显式报预算**（「你最多可输出 N token」）：与去上限互斥——没有预算
  就没有可报的数；且鼓励写长与倾倒诱因同源。
- **把用户原话存进压缩事件、投影时回放**：checkpoint 体积多存一份 80KB 级
  文本，而 raw 本来就在 checkpoint 里，从 raw 现取幂等且零冗余。
- **把用户原话并入摘要输入一起再摘要**：会改变再压缩的 cutoff 算术语义
  （注入消息数混入 original_message_count），且违背分工——原话要的是原文，
  不是再转述一遍。

## 代价

- 压缩后上下文从 ~3.5K 涨到 ~20K+ token：每轮输入成本上升，仍比不压缩
  （766K）便宜一个数量级以上。
- 分块摘要的输入不含装回的用户原话（机制视图不变）：原话不进摘要，极端
  长会话里超预算的最旧用户消息两侧都不可见（与 codex 同款取舍），由
  search_history 的 before_compaction 检索兜底。
- 既有 checkpoint 里旧压缩事件无原话装回（键不存在即跳过），下一次压缩起
  生效——不迁移旧事件。

## 验证

- 单测：`test_compaction_middleware.py`（装回顺序/截断/去图/预算关闭/事件
  缺失回退 + wrap 与 acompact_state 的最终视图计数）、
  `test_compaction_service.py`、`test_compaction_summary_prompt.py`（交接
  基调契约）、`test_hitl_resume_model_wiring.py`；后端全量单测 1589 passed。
- 单轮压缩检查：装回 164 条 = 被压缩区全部真实用户消息（78,195 字符，预算内
  零截断）；摘要 8 节齐全且覆盖全部话题弧（旧近因偏置消失）；不设上限无倾倒
  （5-7K 字符自然收笔）。过程中发现并修复评测 fixture 失真：工具结果曾被
  归一化成用户消息、吃掉装回预算（131/148），改为合成配对的
  AIMessage(tool_calls)+ToolMessage（生产状态真实形状）。
- 20 题三组实测（`results/newproj-20p/`，judge 解析失败 0）：闭卷
  **35% → 77.5%**（macro 40→80、detail 20→70），首次反超不压缩组
  （72.5%）；检索组 77.5%，用户原话装回把闭卷拉到检索水平，检索兜底的
  边际收益在此题库归零（剩余价值在跨会话与工具输出类细节）。
