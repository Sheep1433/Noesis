# 故障运维 Agent 设计

> OpenSpec：`agent-profiles`、`agent-hitl`、`agent-tool-failure-handling`

## 1. 定位

FAULT_OPERATION_QA 面向受控环境的故障诊断。Agent 通过 MCP 获取日志、进程、资源和配置状态，输出诊断过程与建议。当前范围不包含自动沉淀经验、SOP 向量召回或自动执行修复。

## 2. 工具边界

- MCP Server 负责目标连接和实际命令执行。
- Agent 默认执行只读诊断，如日志读取、`ps`、`df`、`kubectl get/describe`。
- 写配置、重启服务、删除资源等高风险操作必须由明确工具能力和 HITL 策略控制。
- 平台不得通过扩大权限或吞异常绕过 MCP 失败。

## 3. 运行流程

```text
用户描述故障
  → 收集目标与症状
  → 选择 MCP 工具
  → 读取证据
  → 更新假设
  → 必要时继续诊断
  → 输出根因、证据、风险和建议
```

网络、权限、超时和基础设施错误使用统一 ToolFailure 分类。命令返回非零退出属于成功返回后的 `command_failed` outcome，不等同于调用异常。

## 4. HITL

HITL 只拦高风险调用。只读诊断不应频繁询问。需要审批时，网页和消息通道使用同一 pending/resume 模型，继续同一 assistant message。

## 5. 安全

- MCP 凭据不进入 prompt、SSE 或落库 tool output。
- 目标地址和工具权限由用户配置与服务端策略共同限定。
- 用户可见错误必须脱敏，详细异常只写服务端日志和 trace。
- Agent 的建议不代表已经执行修复。

## 6. 代码入口

- Agent：`backend/packages/harness/noesis/agents/fault_operation.py`
- MCP loader：`backend/packages/harness/noesis/mcp/loader.py`
- Tool failure：`backend/packages/harness/noesis/errors/tool_failure.py`
- 平台 MCP service：`backend/noesis_server/services/mcp_service.py`
