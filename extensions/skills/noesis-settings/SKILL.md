# Noesis 平台操作与设置

用户问的不是某个业务问题，而是「这个平台怎么用、在哪里配」。你的任务是给出准确的入口路径和步骤，而不是猜测。所有下述入口都真实存在于设置页（左侧导航「设置」进入，路径 `/settings`）。

## 回答原则

1. 先判断用户想达成什么（换模型？接自己的 API？定时跑任务？），再给对应区块的路径。
2. 路径用「设置 → 区块名 → 具体操作」的格式描述，例如「设置 → 模型 → 展开平台模型组 → 点击模型行末的设为默认」。
3. 需要用户自己在界面上完成的操作（填 API Key、点确认），明确说出来——你无法替用户点击设置页。
4. 用户问的能力若在下面清单中不存在，直说平台暂不支持，不要编造入口。

## 设置页区块清单

设置页共九个区块：

| 区块 | 能做什么 |
|------|---------|
| 概览 | 配置健康状态与常用入口 |
| 模型 | 查看平台模型、添加自定义模型服务、设默认对话模型 |
| 画像 | 编辑 USER.md——你的身份、时区等稳定信息 |
| 记忆 | 编辑 AGENTS.md——跨会话偏好与惯例 |
| 扩展 | Skills、MCP、知识库三个入口的汇总跳转 |
| 自动化 | 创建定时任务（自然语言描述或 cron 表达式），运行结果落在固定会话 |
| 通讯 | 接入 Telegram / 飞书机器人，在通讯工具里使用 Agent |
| 系统与迁移 | 通知偏好、系统诊断、设置的导出与导入（不含密钥） |
| 账户 | 账户信息与退出登录 |

## 各区块要点

### 模型

- 模型分两组：平台内置 Provider（默认模型所在）与自定义提供方。
- 添加自定义 Provider 需要：Provider ID、显示名称、API 地址、协议（OpenAI 兼容）、API Key、模型目录。API Key 加密存储，仅本人可用。
- 换默认对话模型：在对应模型行点「设为默认对话模型」。
- 部分提供方有预设模板（下拉选「提供方」时出现的预设项），选预设可少填地址。
- 聊天页输入框的模型选择器也能临时切换模型，但默认模型要在设置页改。

### 画像与记忆

- 画像（USER.md）放「你是谁」：称呼、角色、时区这类不常变的稳定信息。
- 记忆（AGENTS.md）放「你希望 Agent 每次都记住的偏好」：回复风格、常用约定等。
- 两处都是 Markdown 编辑器，保存后对后续会话生效。

### 扩展（Skills / MCP / 知识库）

- Skills：平台预置技能只读，不能改；个人技能两种装法——上传 ZIP，或从 skills.sh 市场安装。已安装的个人技能可删除（右键顶层目录）。
- MCP：编辑器直接写 `mcpServers` 配置后保存；个人配置只接受字面量 URL，不支持 `${ENV}` 环境变量注入（那是平台级配置的能力）。
- 知识库：新建知识库后入库文档，检索走混合检索；页面会提示向量库是否连接正常。

### 自动化

- 两种建法：一句话描述任务让系统解析，或手动选时间 / 自定义 cron 表达式。
- 每次运行的结果落到一个固定会话，可以像普通对话一样继续追问。
- 任务可启用 / 停用，执行记录会保留。

### 通讯

- Telegram：先在 @BotFather 用 `/newbot` 建机器人拿 Token，再回设置页填 Token 与配对的 chat_id。
- 飞书：填机器人凭据，流程类似。
- 配好后可测试连接与消息投递。

### 系统与迁移

- 通知：选择哪些事件在网页或已配置通道里提醒。
- 系统诊断：逐项检查各能力可用性，单项异常不影响其它检查。
- 设置迁移：导出的设置不含密钥；导入前有预览确认。

## 常见问法速查

- 「怎么换默认模型 / 加我自己的 API Key」→ 设置 → 模型
- 「让它记住我喜欢……」→ 设置 → 记忆（或画像，看是偏好还是身份）
- 「装个技能 / 这个技能能删吗」→ 设置 → 扩展 → Skills
- 「接 MCP 服务」→ 设置 → 扩展 → MCP
- 「每天早上九点自动帮我……」→ 设置 → 自动化
- 「在 Telegram 里用」→ 设置 → 通讯
- 「换个设备把设置带过去」→ 设置 → 系统与迁移（导出 / 导入，密钥需重新填）
