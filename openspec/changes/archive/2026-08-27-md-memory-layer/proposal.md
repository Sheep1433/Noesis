## Why

产品定位是平台级个人研究助手（少数人自托管），而记忆皮层按已废弃的运维平台定位设计：条目锁在数据库、经设置页治理、无文件界面、写入门槛错配（个人偏好与目标常被拒收或落入待确认）。个人 Agent 生态收敛的形态是「md 文件 + 索引 + 按需检索」，Claude Code 的记忆组织（MEMORY.md 索引 + 条目文件）是该结构的已验证实现。

用户决策（2026-08-25，经 mem0/memmy/MemSearch 调研与多轮设计收敛）：

- **md 文件是记忆唯一真相**：索引 + 分类条目文件 + 按日情景日志；数据库零新表，Qdrant 第一阶段不使用；
- 记忆按认知科学分类组织：**情景记忆**（journal 流水，只追加）与**语义记忆**（分类条目）两层；
- 写入：会话结束后自动**抽取**（对齐 Claude Code extractMemories），**不需要用户确认**；仅会话中 Agent 主动写入需 HITL 确认；
- 注入：USER.md + 索引进稳定前缀；每个新 Run 小模型按当前问题选条（不同提问注入不同记忆），上轮已注入的不重复；
- 检索：第一阶段 grep + 读文件，**不建向量索引**（记忆规模达到阈值后再升级）；
- 整理：低频后台任务做合并/矛盾/淘汰/压缩，自动执行；
- 一期不含 MCP、历史导入、过程记忆（技能）。

## What Changes

- 新增文件记忆层：`memory/MEMORY.md` 索引（一行一条，行数+字节双保险预算）+ 分类条目目录（一条一文件，含来源引用）+ `memory/journal/日期.md` 情景日志。类型集冻结为五类（preference 偏好 / goal 目标 / decision 决策 / experience 经验 / gotcha 注意事项）——目录即枚举，抽取五选一，不属于任何类型只进情景日志；新增类型需新变更提案。`USER.md` 回归纯手写，引擎永不修改。
- 抽取：会话终态（idle 超时或显式关闭判定）后异步任务读会话消息（有界）、本轮注入清单与现有条目，产出条目写入/更新，自动执行；同一用户串行执行（防并发覆盖）；轻量合并在写入时完成（重复合并、明显过时当场改写）；「不该存」负面清单与相对日期转绝对日期进 prompt。
- 防自强化：注入的条目清单写入 run 的 `memory_context` 字段，抽取时排除对这些条目的复述（用户修正除外——修正是更新信号）。
- 整理：低频后台任务——全局去重、矛盾裁决、淘汰（索引移除，journal 保留原始记录）、索引压缩（超预算时去重/删死指针/条目降级）；自动执行。
- 注入：`USER.md` + 索引注入稳定前缀（会话内不变，cache 最优）；每个新 Run 小模型选条、经 Run 级快照通道注入（同 Run 冻结、alreadySurfaced 去重、按条目年龄加 stale 警告、subagent 不重复）。
- 检索：`search_memory` 工具改为对 memory 目录的 grep/读文件。
- 会话中主动写入：Agent 提议 + HITL 确认（现有机制）后直接写条目文件，立即生效。
- 删除旧记忆链路（五表、状态机、Bulletin 中间件、条目治理 API/UI）。

## Impact

- 数据库：零新表；会话表加「已抽取」标记，run 表复用 `memory_context` 字段记录注入清单。
- 前端：设置页记忆区改为文件管理（索引/条目查看编辑）+ 单一开关；删除四类条目治理 UI。
- 评测：抽取与整理的 fixture 评测（precision/recall/零写入/防自强化/敏感拒收/修正更新）、膨胀率、paired 开/关成功率（走 prod 模型通道，避免免费配额阻塞门禁），release gate 延续 fail-closed。
- 归档前置：`add-run-aware-memory-cortex` 以「11.1 未过、被本变更取代」归档。
- 后续阶段（本变更不做）：Qdrant 影子索引（记忆规模触发）、注入升级为持久追加式 reminder、过程记忆（技能抽取）、历史导入、MCP 跨工具共享。
