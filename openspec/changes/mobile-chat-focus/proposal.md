## Why

当前移动端聊天页同时展示全局导航、品牌顶栏、助手类型按钮和大块欢迎说明，压缩了消息区与输入区。用户也需要先理解“智能问答 / 智能体”的实现差异，才能选择入口，不符合按任务意图使用产品的习惯。

## What Changes

- 移动端聊天页改为沉浸式布局，常态只保留极简会话顶栏、消息区和 Composer。
- 将 `COMMON_QA`、`SUPER_AGENT_QA` 的产品入口改称“聊天”“任务”，内部 `qa_type` 与 `/api/chat` 请求保持不变。
- 新建会话时通过模式选择面板选择“聊天”或“任务”；已有消息的会话切换模式时创建新会话，避免清空当前会话。
- 移除 Composer 上方常驻的问答类型按钮；故障运维作为“任务”下的专项入口保留。
- 模型作为高频设置常驻在 Composer `+` 号旁边；附件、知识库、MCP、Skills 与会话文件继续收在工具菜单中。
- 移动端隐藏品牌欢迎区、底部全局导航和常驻文件入口；空白会话保留当前模式的紧凑能力卡片，历史、产品导航、会话文件及工具能力通过抽屉或 Composer 菜单访问。
- 设置与知识库管理页在移动端使用内容优先布局，不显示底部全局导航及其占位。
- 前端导航不再展示测试用例入口，现有页面路由与后端能力暂时保留。
- Todo、HITL 与断线提醒仍可在执行期间临时展示。
- 桌面端维持现有外壳和全局导航，但采用同一套模式选择语义，避免两套产品命名。
- 不修改后端 API、SSE 事件或 `qa_type`，无破坏兼容变更。

## Capabilities

### New Capabilities

- `chat-mode-experience`: 规定聊天页的“聊天 / 任务”产品模式、新建与切换行为，以及移动端沉浸式布局。

### Modified Capabilities

- `chat-composer`: Composer 不再使用常驻问答类型按钮，工具入口在紧凑菜单中按当前模式展示。
- `platform-chat`: 聊天页对 `qa_type` 的用户可见命名与会话切换行为发生变化，但路由契约不变。

## Impact

- 主要影响 `frontend/src/views/chat.vue`、移动端应用外壳、导航组件、默认欢迎页和 Composer 工具栏。
- 需要补充前端组件/交互测试，验证移动端可见元素、模式映射和已有会话切换保护。
- `/api/chat`、历史会话字段、SSE 契约和后端 Agent 装配均不变。
