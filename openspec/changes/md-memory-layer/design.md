# 设计：md 文件记忆层（索引 + 分类条目 + 情景日志）

## 1. 总原则

- **md 文件是记忆唯一真相**；数据库只挂两个既有字段（会话「已抽取」标记、run 的注入清单），无新表、无向量索引。
- 介质按使用者定：人读写的进文件；机器需要的状态挂在现有表字段上。
- 记忆分两层（认知科学分类）：**情景记忆** = 按日 journal 流水，只追加永不改写，是证据与兜底；**语义记忆** = 分类条目文件，被整理（合并/更新/淘汰）。淘汰 = 从索引移除（journal 永在，可搜可重建），不是删除。
- 引擎写入自动执行、无确认；**唯一 HITL 场景是会话中 Agent 主动写入**。
- 命名对齐 Claude Code：写入叫**抽取**（extractMemories），低频合并叫**整理**（Dream/consolidation）。

## 2. 文件结构

```
.noesis/users/{user_id}/
├── USER.md                     # 纯手写用户上下文，引擎永不修改
└── memory/
    ├── MEMORY.md               # 索引：按类型分组，一行一条
    │     ## 偏好
    │     - [文档格式] 一律表格、简体中文 → preference/document-format.md
    │     ## 目标
    │     - [学习路线] 正在学 Node.js，下一步做 CLI → goal/nodejs-learning.md
    │     ## 决策
    │     - [包管理] 统一 pnpm → decision/package-manager.md
    │     ## 经验
    │     ## 注意事项
    ├── preference/<slug>.md    # 一条记忆一个文件
    ├── goal/<slug>.md          # 进行中的目标/项目（时效最强，整理重点检查完结）
    ├── decision/<slug>.md
    ├── experience/<slug>.md
    ├── gotcha/<slug>.md
    └── journal/<YYYY-MM-DD>.md # 情景流水：当日各会话的摘要条目（含会话 id）
```

**索引预算双保险**：`MEMORY.md` 设行数（200 行）与字节（25KB）双上限，任一触发即视为超预算；超预算触发整理压缩——去重、删除指向不存在文件的死指针、啰嗦条目降级（索引只留一句话，详情在条目文件），不静默截断（静默截断会无声丢弃最旧条目）。

条目文件内容：结论正文 + Why（可选）+ 适用条件（怎么应用）+ 来源（`来源: 会话 {sid[:8]} · {date}`，可多条）+ 更新时间。文件名 slug 由抽取生成（短横线小写，撞名追加序号）。

### 类型系统（冻结）

| 类型 | 回答的问题 | 维护语义 |
|------|-----------|---------|
| 偏好 `preference` | 用户要什么样的输出/行为 | 最稳定，几乎不淘汰 |
| 目标 `goal` | 用户现在在做什么 | 时效最强，整理任务重点检查完结/演进 |
| 决策 `decision` | 我们定了什么、为什么 | 稳定；被推翻时改写并留来源 |
| 经验 `experience` | 什么做法有效 | 稳定 |
| 注意事项 `gotcha` | 什么要避开 | 稳定 |

类型集固定：**目录即枚举**（五个目录是全部合法类型）；抽取必须五选一，**哪类都不是的内容只进 journal 情景日志、不进语义层**——fallback 是日志而非新类型；新增类型必须开新变更提案（与改数据库 schema 同等待遇）。

## 3. 抽取（会话终态，自动）——水位增量

```
会话 idle 超过阈值（config.session_idle_minutes）
  → sweep 发现「最新合格消息序号 > 水位」的 root 会话
      （subagent 会话不抽：结论经父会话终态通知回流）
  → 异步抽取任务（同一用户串行执行，防并发写覆盖）
  → 读：水位之后的新消息段
       + 水位前 2 条消息做衔接背景（指代消解，mem0 同款）
       + 超预算保段头 20%（目标陈述）保段尾 60%（结论），中间标注省略
       + 本轮各 Run 注入清单（run.memory_context 聚合）
       + 现有条目（轻量合并判定的输入）
  → LLM 判断：先过「不该存」负面清单，再判值得记什么、类型是什么（五选一）
  → 轻量合并：与现有同类条目重复 → 更新该文件并追加来源；明显过时 → 当场改写
  → 新建条目文件 + 索引行 / 更新既有条目；相对日期改写为绝对日期
  → journal 追加当日情景条目
  → 推进水位（memory_extracted_seq = 本段最大序号）
```

水位语义（对齐 Claude Code extractMemories cursor / OpenClaw ingestion 水位，
2026-08-26 调研定稿）：**成功才推进，失败保留原水位**（下次 sweep 重试同一段）；
开关关闭期间照推（不回溯）；新段无合格文本也推进（避免反复扫描）。

**「不该存」负面清单**（对齐 Claude Code）：grep/读文件/代码本身能得出的不存；CLAUDE.md/USER.md 已写的不存；临时任务状态与当前对话上下文不存。核心原则：只记推不出来的东西。

守卫：敏感内容拒收；本轮注入过的条目被复述不记录（防自强化；**用户修正除外**——对注入条目的修正是更新信号，应更新条目）；无价值会话零写入；单次抽取至多 3 条新条目，超出部分只进 journal。进程崩溃恢复：下次触发（新会话终态或整理任务运行）时扫描未抽取的终态会话补跑。

## 4. 整理（低频后台，自动）——AutoDream 门控

触发门控（对齐 Claude Code AutoDream）：距上次整理 >
`consolidation_min_interval_hours`（默认 24h）**且**期间新抽取会话数 ≥
`consolidation_min_new_sessions`（默认 5），双条件同时满足才跑（无活动日
不空转）；门控检查挂在抽取 sweep 循环尾部。状态存
`memory/.consolidation_state.json`。单次任务职责：

- 全局去重（合并同义条目，来源合并）
- 矛盾裁决（新旧冲突按时间与证据取舍，改写条目）
- 淘汰（过时/低价值条目从索引移除并删文件——journal 保留原始记录；**goal 类重点检查**：完结的目标改写为结果性经验或淘汰，演进中的更新措辞）
- 索引压缩（超预算时去重、删死指针、啰嗦条目降级）
- 情景信号 Gather（AutoDream 对应阶段）：近 7 天 journal 内容进整理
  prompt，识别跨会话模式——反复主题、多次纠正（不逐条处理，只作信号）

自动执行无确认；质量由评测门禁与 journal 可重建性兜底。

## 5. 注入（每 Run 选条）

```
稳定前缀（会话内不变）：USER.md 全文 + MEMORY.md 索引
每 Run：小模型（廉价模型一次调用）读索引 + 当前用户问题 → 选中相关条目 → 读出条目文件正文
  → Run 级稳定快照注入：头部「以下为历史经验，可能过时」
     + 按条目年龄附 stale 警告（如「该条目保存于 N 天前，使用前先验证」）
```

- 同 Run 冻结（tool loop 与 HITL resume 期间内容不变）；新 Run 按新问题重新选条（不同提问注入不同记忆，对齐 Claude Code findRelevantMemories）；subagent 不重复注入。
- alreadySurfaced 过滤：上一 Run 已注入的条目本 Run 不再重复注入，控制上下文增长。
- 任一依赖失败零注入、Run 继续。
- 记忆量很小时（索引 + 全部条目 < 预算）直接全量，跳过小模型调用。
- 注入条目清单写回 run.memory_context（供抽取防自强化；多 Run 会话由抽取聚合各 Run 清单）。
- 不截断单条条目；索引超预算走整理压缩（见 §2）。

### 注入通道与 prompt cache

cache 是前缀匹配，注入纪律只有一条：**写进对话后不改写，或只放会话内不变的内容**。

- USER.md + 索引（会话内不变）→ 稳定前缀通道，跨 Run 缓存命中。
- 每 Run 变化的选条正文 → Run 级 late-context 快照通道。代价有界：每 Run 第一次模型调用重算上一轮 token，Run 内后续模型调用全部命中；且该槽位本就因 current_time 每 Run 变化、代价已被摊沉——记忆放这里零边际 cache 成本。
- **禁止**把每 Run 变化的内容放进 system 前缀区（会使全历史每轮重算）。
- 持久追加式 reminder（Claude Code system-reminders 模式，零损失）为后续优化项，第一阶段不建消息流持久化机器。

## 6. 检索（工具）

`search_memory` 改为对 memory/ 目录的 grep + 读文件（按类型目录过滤、关键词匹配、返回条目原文），预算限制沿用。语义向量检索为后续阶段（见 §9）。已知局限：关键词匹配是字面匹配，中文同义表述（记「偏好」、查「喜欢」）不命中——靠注入时小模型选条弥补，规模超阈值后由影子索引解决。

## 7. 会话中主动写入（唯一 HITL）

Agent 会话中判断值得立即记忆（或用户说「记住这个」）→ 提议写入条目 → HITL 确认（现有确认机制）→ 直接写条目文件 + 索引行 → 下次会话生效。

## 8. 治理

- 用户直接编辑文件 = 最高权限；引擎下次抽取基于文件现状增量工作，不覆盖用户改动（写入前重读）。
- 无独立版本历史：journal 保留全部原始素材，条目可从情景层重建。
- 治理四问：去重 = 写入时合并 + 整理全局扫描；过期 = 时效措辞 + 整理更新；降级 = 索引移除（journal 可搜）；不实 = 来源引用可回查会话 + 直接删行 + 评测门禁。

## 9. 阶段划分

- **本变更（第一阶段）**：上述全部；无向量索引、无数据库新表。
- **后续阶段**（各自独立立项）：记忆规模超阈值后引入 Qdrant 影子索引（索引条目，写后同步 + 定期对账）；注入升级为持久追加式 reminder（消除每 Run 首调用的上一轮重算）；过程记忆（重复工作流抽取为技能）；历史会话导入；MCP 跨工具共享。

## 10. 评测（fail-closed）

- 抽取 fixture：会话 → 期望条目（precision/recall/无价值会话零写入/防自强化/敏感拒收/注入条目被修正→条目更新）。
- 整理 fixture：旧条目 + 新日志 → 期望合并结果；索引超预算 → 期望压缩结果。
- 膨胀率（每百轮会话文件增量）、paired 记忆开/关任务成功率差值 CI（走 prod 模型通道）。
- 抽取质量未达标不得默认开启。
