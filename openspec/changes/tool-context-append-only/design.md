# Design: 工具上下文 append-only 投影与预算收敛

## 核心不变量

**同一份历史投影两次，模型看到的内容逐字段一致；历史在发送之后永不被改写。**

Prompt 缓存按前缀精确匹配：第 N+1 次请求与第 N 次请求只要在半中间差一个字节，从该位置起的缓存全部作废。因此上下文投影只有一种缓存安全的形态——**所有定型在内容第一次进入有效历史时一次完成，之后只追加**。本设计把这个性质从「多数情况成立」升格为中间件的硬契约，并用单元测试钉死（`test_projection_is_stable_across_model_calls`）。

## 预算中间件

### 单条预算与入口定型

保留单条结果 24k 字符预算（`runtime.tool_output_max_chars`），删除两个机制：

- **参数卸载的滑动窗口**（原「最近 12 条消息内保留原文」）：窗口边界每前移一格就改写一条已发送消息，是 step 16→17 输入反降的直接根因。改为大参数（`content` / `new_string` 超单条预算）在第一次进入有效历史时即替换，替换记录按内容 hash 键控重放，与工具结果替换同一套 record 机制。
- **批次合计层**（原 48k/批）：单条预算已约束每条结果的上限；合计层额外替换的是「中间大小」结果，主要受害者是并行检索批次。上下文总量护栏归压缩层（Compaction），该层删除后职责不再重叠。

替换梗概从固定头 400 + 尾 200 提为头 2000 + 尾 1000（参数梗概头同额、尾 0）：被替换内容的有效可见量提升 5 倍，减少模型为看内容重读 artifact 的额外轮次。

### 投影幂等

替换文本本身可能超过预算（尤其小预算配置下），若被当作新的超限输入二次替换，第二次投影就会改写第一次发送的内容——违反核心不变量。参数替换文本以 `[large content omitted` 为稳定前缀哨兵：已替换文本免于再替换。工具结果侧由既有 `tool_result_replacement` / `artifact_path` 元数据标记保证同一性质。

## read_file 源头封顶

上游 read_file 的截断开关与「结果驱逐到 artifact」共用 `tool_token_limit_before_evict` 参数；Noesis 为让预算中间件单点拥有替换语义（保留 status / errorCategory / outcome）将其置 None，连带使 read_file 失去源头上限。为不重新启用双份卸载，read_file 封顶在 Noesis 层独立实现：stack 装配 FilesystemMiddleware 后原地包装其 read_file 工具（与 execute 工具后台化替换同一模式），输出超 `runtime.read_file_max_chars`（默认 20,000，约为单条预算的 85%）时截断并附「按行号用 offset 续读」提示。

上限取预算的 85% 而非相等：留出包装开销余量，保证新鲜读取稳落预算内、永不触发事后替换。截断发生在源头且截断内容直接可见，模型自行分段续读——「卸载 → 读 artifact → 再超限 → 再卸载」的追逐循环从机制上消失。

## Runtime Context 冻结块

动态上下文的三个事实决定其形态：模型需要的是「今天几号」而非「现在几点几分」；时间戳逐轮变化则头部内容逐轮不同；头部改写一次等于整段前缀作废（缓存重建代价与对话长度成正比）。因此：

- **头部冻结块**：会话首轮把 `Today's date is YYYY-MM-DD（时区）` + workspace 渲染成块，存 private state；此后每次请求以 messages[0] 位置投影（位于 system prompt 与首条用户消息之间），内容逐字节不变。子 Agent 经 private state 继承父会话冻结块（同会话同日期，语义一致）。
- **跨日尾部纠正**：当前日期 ≠ 冻结日期时，冻结块保留过期日期不动，本轮请求尾部追加 `Today's date is now …` 声明。尾部追加只花费自身的 token，不动前缀。
- **附件尾部声明**：附件集合与上次记录不同且非空时，尾部追加 `Attachments available: …`；集合不变不重复。附件是逐轮变化信息，不属于冻结块。
- **中途注入路径退役**：原「每轮插在最后一条用户消息前、不进历史」的 `insert_late_context` 删除——位置与内容双变是每轮前缀分叉的根源。

Checkpoint 恢复依赖 private state 持久化；无 checkpoint 的冷重建会按当日重新冻结（同日无差异，跨日付一次性前缀重建，属可接受的会话恢复代价）。

## web_fetch 单份正文

输出 JSON 只保留 `results[0].snippet` 一份正文：顶层 `content` 是同一文本的完整拷贝，无任何消费方（retrieval 注册与前端来源面板均只读 `results`）。`fetch_max_chars` 4096 → 16000：单次抓取约 4k token 有效信息（深度研究的合理粒度），单份存储后单次输出 16k，稳落单条预算内。

## 备选方案

- **保留滑动窗口、把窗口计数改为「不滑动」**（如按 tool_call_id 白名单豁免近期写入）：否决。窗口本身就是改写源——任何「先保留、后替换」的两段式都必然在某个时刻改写已发送内容；只有入口定型满足核心不变量。
- **压力触发式批量清理**（上下文占用超阈值时一次性清理旧结果）：否决。触发式设计需要引入阈值状态机与触发时机的判定复杂度，且触发瞬间仍是一次全量前缀作废；入口定型 + 压缩层已覆盖其全部收益。触发式的「保鲜区」收益（近期大参数保留原文）在实测中无功能必要性——24k+ 参数是整份文件内容类一次性数据。
- **read_file 直接调小上游 `tool_token_limit_before_evict`**：否决。该参数同时控制结果驱逐，调小会在 20k 处重新启用上游卸载，与预算中间件形成双份替换且上游不保留 status / errorCategory / outcome。
- **Runtime Context 每条用户消息携带日期戳**：否决（对冻结块方案）。语义等价且同样 append-only，但每轮 user 消息都多一行重复信息；冻结块 + 尾部纠正把常态成本压到零（同日无任何额外注入）。

## 语义消费者说明

| 新增物 | 消费场景（本 change 内已承诺） |
|--------|------------------------------|
| `runtime.read_file_max_chars` 配置项 | stack 装配层 read_file 包装的封顶值；运维可独立调整读取粒度 |
| `_ARG_REPLACEMENT_PREFIX` 前缀哨兵 | 投影幂等测试与第二次投影的免替换判定 |
| 冻结块 / 尾部纠正的 private state 键 | 子 Agent 隔离继承（`_PRIVATE_SUBAGENT_KEYS` 聚合）与 checkpoint 重放 |
| `render_head_block` 导出 | 单元测试与 ContextResolver 预览链路复用同一渲染 |
| web_fetch 单份输出形态 | retrieval parts 注册（`retrieval.py` 读 `results`）与前端来源面板 |

## 测试与验收

- 预算中间件：投影稳定性（两次投影逐字段一致）、参数入口定型（新旧消息无差别）、批次合计删除回归（并行结果整体放行）、梗概长度、幂等哨兵。
- read_file 封顶：超限截断 + 提示、下限放行、异步路径一致、工具身份与 schema 保持、缺工具静默跳过。
- 动态上下文：冻结块跨 run 一致、跨日尾部纠正、附件声明一次、无 provider 清理、渲染布局。
- web_fetch：单份正文断言。
- 全量后端回归绿（既有契约测试不动——展示层、SSE、落库行为零变化）。
- 真实场景验收（人工）：深度研究任务中 read_file 超限显示续读提示且模型用 offset 分段；并行搜索结果不再被摘要替换；多步 run 缓存命中率向结构值（≈ 1 − 新增/累计）收敛。
