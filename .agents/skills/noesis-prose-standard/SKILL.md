# Noesis 文字标准（可读性 + 去 AI 味）

写到什么程度算「好读」。**判断由 Agent 语义做出，探针只负责发现候选**——机器能数的（段落长度、嵌套深度）只是线索，命中后必须逐条人工判断，不许机械套规则改写。修残留（"原先/被 review 否决"类会话视角）用 `noesis-prose-hygiene`；本 skill 管的是「写得好」，两者边界：那个管清除缺陷，这个管正向质量。

## 五条底线

1. **结论先行**：每节第一句给结论或主张，论据跟在后面。读者只读每节首句就能拼出全文骨架。
2. **现算态**：写当前状态，不写你怎么推导出来的。推导过程、方案对比的中间步骤属于决策记录的备选方案节，不属于架构文档。
3. **表格只放可枚举事实**：格子里是名称、路径、数值、是/否；解释和论证写进正文，禁止在单元格里塞句子。
4. **嵌套不超过两层**：列表套列表到第三层就是结构病的信号——要么拆小节，要么改成 prose。
5. **加粗只标一级重点**：一段最多一处。什么都加粗等于什么都不重要。

## 锚定实物

写 how-to、架构说明、机制文档时，**先声明本文对照哪些真实模块/文件验证**（一句话列出路径即可），正文引用的路径与行为以这些实物为准——不写凭空推演的结构。声明本身也是读者的入口：照着做的人知道去哪核对。文档与实物冲突时，改文档（或发现是代码该改，就按 bug 流程走），不允许两者各说各话。

## AI 味症状清单（命中即改）

**套话与空洞开场**

- 「随着…的发展」「在…背景下」「不可否认」「值得注意的是」——删。
- 第一节 100 字内必须出现具体问题、场景或结论；「本文将详细介绍…」这类元叙述删掉直接写内容。

**结构机械感**

- 每个 H2 都是同一节奏（定义→优点→缺点→总结 / 先下定义再贴代码再总结）——允许各节形态不同，不强求对称。
- 连续三段以相同连接词开头；每节结尾都有一句总结升华——删总结句，做「删句测试」：随机删 3 句判断句或总结句，删完不影响理解就重写它们。
- 小节不为凑结构硬拆：某节只讲一个坑、某节只讲一个取舍，都是合法形态。

**措辞同质化**

- 搜并替换：`至关重要`、`深入探讨`、`全方位`、`赋能`、`助力`、`无缝`、`旨在`、`不仅…而且…`。
- 同段反复出现「关键」「核心」「重要」；破折号与排比堆砌。
- 「这解决的不是 A，而是 B」「两者不在一个层面」这类高概括句后面必须跟具体例子，否则删。

**命题稀释**

- 一句话能说清的不摊成一段。形容词和强调词删掉后命题不变的，全删。
- 「像结论卡片一样完整」的句子重写：宁可短句、允许停顿感。

**段落墙与状态标注**

- 段落墙：一个段落塞多条规则加括号补充——拆开，或把细节降级到它的归属文档。
- implementation-status 标注（「已实现！」「未来：…」）删掉：状态会腐烂，仓库布局与代码本身携带状态。
- 手抄目录：文档复述代码/配置里已有的清单（事件表、路由表、字段表）——链接到权威来源或契约测试，不抄第二份。
- implemented 决策记录里的 spec 腔（「应当」「迁移计划」「验收清单」）：implemented 记录写「是什么」，现算态。

**虚假权威**

- 没实测的数据不写或标注「未实测」；不假装做过压测、上线、故障。
- 保留棱角：「尚未验证」「可能过度设计」是合法表述。

## 发现探针（跑完必须语义判断）

```bash
# 套话词表命中（逐条判断是否真套话）
rg -n '至关重要|深入探讨|全方位|赋能|助力|无缝|旨在|随着.*的发展|不可否认' <目标文件>

# 超长段落（>150 字的中文段是候选，技术必要的不算病）
awk 'BEGIN{RS=""} length($0)>450 {print NR": "length($0)" 字符"}' <目标文件>

# 嵌套列表（缩进两层以上的 bullet 是候选）
rg -n '^\s{4,}[-*] ' <目标文件>

# 单元格长句（表格行内含 30+ 字的格子是候选）
rg -n '^\|.*\|.{30,}.*\|' <目标文件>
```

每个命中都要回答「这真的是病吗」——技术文档里一个 200 字的机制说明段落是健康的，一个 200 字的总结段才是病。

## 终检

1. 只读每节首句，能否拼出全文骨架？（结论先行的可证伪检验）
2. 把结论单独抽给同事看，10 秒内知道这篇讲什么、值不值得读？
3. 删句测试（见结构机械感）。
4. 对照五条底线逐条过一遍。

## 与其他标准的关系

- `noesis-prose-hygiene`：清除会话残留（视角病），本 skill 是正向质量（可达性）；先 hygiene 后 standard。
- 代码注释与 JSDoc 的必写覆盖见 hygiene skill 的「按位置覆盖底线」，本标准适用于其措辞质量。
- 正式 spec/design 的叙述须第一性自洽（见 `openspec/AGENTS.md`），外部调研引用只出现在 `docs/research/`。
